# xxd.png —— 字节即像素

> 平台定位：**Bugku「这亦是一种图片」**（MISC / 20 分 / 作者 `sudopacman` / id=3080）。
> 官方描述：*"如果一个文件能被识别成图片，由像素点构成，能通过像素点读取有效信息，那它就是图片(确信)"*
> 参考 WP：cheyenne（2026-07-20）给出的三行 Python（见 §4）。

## 0. 一句话

`xxd.png` 根本不是图片：PNG 魔数只留了个头，IHDR 的宽/高全是 0，也没有 IDAT / IEND。
真正的内容是**把文件转成十六进制文本后，把每个 hex 字符当成一个像素**画出来的一行字。

正确读法：

```python
h = open('xxd.png', 'rb').read().hex()          # 1696 字节 -> 3392 个 hex 字符
# 每 32 个 hex 字符一"列"，转置成 32 行 x 106 列
# 判据：hex 字符 != '0' 即为墨点
```

得到位图：

```

```

**提交（全小写）：`<历史答案已移除>`**

> ⚠️ **是 `K` 不是 `H`。** 这是本题唯一的坑，也是我们第一次做错的地方，详见 §1.5。

## 1. 已验证事实

### 1.1 文件结构（逐字节看的）

| 偏移 | 内容 |
|---|---|
| `0x00–0x07` | `89 50 4e 47 0d 0a 1a 0a` —— PNG 标准魔数（**诱饵**） |
| `0x08–0x0F` | `00 00 00 0d 49 48 44 52` —— IHDR 的长度 + 类型（**只有头，没有身子**） |
| `0x10–0xB5` | 全 `00` |
| `0xB6–0x5D7` | **161 个非零字节** —— 就是正文 |
| `0x5D8–末尾` | 全 `00`（凑到 1696 = 16 × 106） |

- 文件 1696 字节，非零 **161** 个（约 9.5%）。
- 没有 IDAT、没有 IEND、没有 CRC。**解析器一个字都读不出来**，所以它连"坏图片"都不算，只是拿 PNG 头当障眼法。
- `1696 = 16 × 106`；写成 hex 后共 **3392 = 32 × 106** 个字符。

### 1.2 正确的读法：hex 字符级，列主序，步长 32

```
hex 字符索引 k   ->   列 i = k // 32 ， 行 j = k % 32
```

也就是把 3392 个 hex 字符按 **每 32 个一组**切块，每块成为图像的一"列"，共 106 列。

**为什么 `xxd` 是文件名提示：** `xxd` 每行输出 16 个字节；而 16 字节写成 hex 正好 **32 个字符** —— 每行 32 个 hex 字符，正是图像的"一列"。文件名在提示"拿 hex 文本按 16 字节一行来看"。

**步长为什么是 32（= 16 字节 × 2）：** 字节级扫描出列高 16（见 §1.7），hex 字符级翻倍即 32。

### 1.5 ★ 唯一的坑：`K` 不是 `H`（第一次做错的地方）

**第一次用"字节级"（1 字节 = 1 像素，16 行）读，把 #8 读成了 `H`。**

原因：字节级把垂直分辨率砍了一半。#8 的原始值：

```
byte r6   0d 00 00 00 00 0d    [13,0,0,0,0,13]
byte r7   ef 0f 0c 0f 70 00    [239,15,12,15,112,0]
byte r8   9c 00 00 20 01 00    [156,0,0,32,1,0]
byte r9   90 00 00 00 00 c0    [144,0,0,0,0,192]
```

字节级二值化后（`!=0`）：

```
r6  #....#
r7  #####.     <- r7 那一行有 5 个连续墨点
r8  #..##.
r9  #....#
```

`r7 = #####.` 看起来像"贯通的中横" → 判成 `H`。

**但拆成半字节级（32 行）后，真相是：**

```
row13  |#....#|
row14  |#...#.|     <- 右上斜笔
row15  |####..|     <- 交汇处
row16  |#..#..|     <- 右下斜笔
row17  |#...#.|
row18  |#....#|
```

**左竖 + 右上斜 + 右下斜 —— 这是 `K`。**

根因：`r7` 的值是 `[239,15,12,15,112,0]`，**只有首尾是实墨（239 / 112），中间 `15 12 15` 是抗锯齿噪声**。
字节级把它们一视同仁算成"有墨"，于是 `#....#` 变成了 `#####.`，斜笔被压平成中横。

**结论：这类题必须用 hex 字符级（stride = 字节级 × 2）读，不能用字节级。**
差别只在垂直方向的分辨率，但足以把 `K` 变成 `H`。

**交叉验证：** Bugku 该题公开 WP（cheyenne）给出的位图就是 `<历史答案已移除>`，与本结论一致。

### 1.6 另一个坑：括号必须是花括号

提交 `flag(sah4na)` / `flag[sah4na]` 之类都会被拒。括号形态已被像素证据钉死是**花括号**：

```
#5 左括号 {          #12 右括号 }
 row11  ..#  00 00 02    row11  #..  0a 00 00
 row13  .#.  00 7f 00    row13  .#.  00 65 00
 row15  #..  0c c0 00    row15  ..#  00 50 0f
 row17  .#.  00 66 00    row17  .#.  00 5c 00
 row19  ..#  00 f0 0c    row19  #..  06 50 00
```

判据：**中间行（row15）有两个像素**（`0c c0` / `50 0f`），且分别往**左**、往**右**凸。
- `{`：主干在中间列，中缝向左挑一个钩 → 中间行 2 px ✓
- `(`：3 列宽里每行只有 1 px（右→中→左→中→右的单像素弧）→ 中间行只能 1 px ✗
- `[`：左竖 + 上下两条横，没有中间那个钩 ✗

### 1.7 排错记录（试过但排除的）

| 尝试 | 结果 |
|---|---|
| 字节级列主序 stride=16 | **能出字，但会把 `K` 压成 `H`**（本题的坑） |
| 行主序 width=16（106×16） | 与字节级列主序**互为转置**，同一份网格，无新信息 |
| 列主序 stride=8 / 32 | 无横笔画，噪声 |
| 每字节 LSB / MSB 位平面 | 无可打印串 |
| 8 个位平面逐个拼装 | 全都无可打印串 |
| 多阈值扫描 T=1/16/32/64/100 | 字节级下字形稳定（但都是错的那个 `H`）；**问题不在阈值，在分辨率** |
| zip 内其它文件 / 注释 | `xxd.png.zip` 只有 `xxd.png` 一个文件，无 archive comment |

## 4. 题型归纳

**sig: `stego.png_byte_as_pixel`**

识别特征（满足任意两条就该试）：

1. PNG 魔数对，但 **IHDR 宽/高为 0**、无 IDAT/IEND，文件尺寸很小；
2. 非零字节比例很低（本例 9.5%），且集中在文件中部一段；
3. 文件名/题目名提到 `xxd`、`hex`、`dump`、`transpose`、`row/col`；
4. `file` 认不出图片，图片查看器打不开。

处理步骤：

1. **先做 hex 字符级**（`bytes.hex()` → 每 32 个字符一列 → 转置），不要先做字节级；
2. 判据用 `hex字符 != '0'`（等价于"该半字节非零"）；
3. 跳过第 0 列（魔数残影）；
4. 打印 ASCII，按空列切字；
5. 矮字靠**笔画走向**认字，不靠轮廓像不像；**斜笔 vs 中横必须看半字节级才能分清**。

**参考 WP（cheyenne, 2026-07-20）原文：**

```python
from PIL import Image
import numpy
Image.fromarray(numpy.array([i == '0' for i in open('<本机路径>', 'rb').read().hex()]).reshape(-1, 32).T * 255)
```
