# 战例：EasyRsa（链式 RSA，共用素因子）

- 来源附件：`<本机路径>`（双层 zip：外层 → `tempdir/CRYPTO附件/task.zip`）
- 题面文件：`task.py` + `output.txt`（12 个 1023 位模数）
- 完成时间：2026-10-10
- 结论：**已解决**，唯一解，正推复算与题目给的 `c` 逐位一致
- flag：`GWHT{gixkJl7SJTcpLOL9zqwo}`（注意是 **`GWHT{}`** 格式，不是 `flag{}`）

## 一、已验证事实

### 1. 题目结构

```python
m = bytes_to_long(flag)
e = 65537
for i in a:              # output.txt 每一行是一个模数
    n = int(i)
    c = pow(m, e, n)
    m = c                # 链式：上一步的密文当下一步的明文
print 'c = %s' % (m)
```

即 `m_0 = flag`，`m_{i+1} = m_i^e mod n_i`（i = 0..11），给出 `m_12 = c`。
共 **12 个模数，全部 1023 位**。

### 2. 漏洞：12 个模数共用同一个 512 位素因子

两两 GCD 一跑就全部命中同一个值：

```
p = 7552850543392291177573335134779451826968284497191536051874894984844023350777357739533061306212635723884437778881981836095720474943879388731913801454095897  (512 bits)
```

`gcd(n_i, n_j) = p` 对**所有 66 对**都成立 → 每个 `n_i = p * q_i`，12 个模数全可分解。
这是本题唯一需要的漏洞，没有任何高级技巧。

### 3. 逆推的坑（这题真正值得记的点）

RSA 解密只还原**模 n_i 的余数**：

```
m_i ≡ m_{i+1}^{d_i}  (mod n_i)
```

但真实的 `m_i` 还额外满足 `m_i < n_{i-1}`（它是上一步模 `n_{i-1}` 的结果）。
如果直接 `pow(m_{i+1}, d_i, n_i)` 就当答案，**约有一半概率是错的**——
因为 `m_i` 可能大于 `n_i`，解密出来的是 `m_i mod n_i` 而不是 `m_i`。

解法：候选为 `r + t * n_i`（`r` 为解密余数，`t = 0,1,2...`），
用约束 `m_i < n_{i-1}` 卡住；所有 n 都是 1023 位、彼此比值 < 2，所以每层只有 1~2 个分支。
做 DFS，最后用「`m_0` 必须能解成可打印 ASCII」剪枝。

实测：**候选解恰好 1 个**，不需要靠人眼挑。

### 4. 验证（三重）

| 验证项 | 结果 |
|---|---|
| 解唯一性 | DFS 全空间只有 1 个候选 ✅ |
| 正推复算 | 从 `m_0` 依次 `pow(m, 65537, n_i)` 12 次，得到的 `c` 与题面给的 `c` **完全相同** ✅ |
| 可读性 | `m_0 = 114640482520002518194201611182675907293212296849507622554398589` → ASCII 可打印 ✅ |

### 5. 算力分工

本题**纯本地 Python 秒解**，没用 Kali / 本地模型 / REA——
成本排序上 GCD 是 O(1) 级别的，派给 Kali 反而是浪费。
（这跟昨晚 flag0 必须靠 Kali hashcat 正好相反：什么时候用什么算力，取决于最便宜的那一步在哪。）

## 二、未验证假设

1. `p` 是素数——按 512 位 RSA 素因子的惯例当它是，但**没有跑 Miller-Rabin 确认**。
   不影响求解（`d_i` 依赖 `phi = (p-1)(q_i-1)`，若 `p` 非素数则 `phi` 算错，但正推复算已通过，等于间接证伪了这个担心）。
2. `q_i` 是否也两两共用——**没查**（已经能解，没必要）。
3. flag 前缀 `GWHT` 具体是哪个赛事的缩写——**没查证**。
