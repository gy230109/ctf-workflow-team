## 3. 解题链路

```
x96（ELF32 i386，无 section header）
  │ ① 入口 cmp cs, 0x23 → retf → 0x33:0x804806c（切到 64 位段）
  │ ② read(0, buf, 36)
  │ ③ for ecx in 0..35:  bl = ror64(0x358d0150819cf3c4, ecx) & 0xff
  │                       if buf[ecx] ^ bl != blob[ecx]: fail   ; blob @ 0x80481c3
  ▼
buf[ecx] = blob[ecx] ^ (ror64(0x358d0150819cf3c4, ecx) & 0xff)
  ▼
输入 → 实跑输出 Correct! → flag
```

## 5. 已验证事实

1. `x96` 为 **ELF32 i386**（`e_ident` 类=1，machine=3=EM_386），**无 section header**（`e_shoff=0`）；
   `e_entry = 0x8048054`。
2. 入口先 `cmp cs, 0x23`，再 `retf` 切换到 **`0x33:0x804806c`** ——
   即从 32 位模式跳进 **64 位代码段**（题目"中立的双方读同样的字节却解释不同"的梗即指此）。
3. 64 位段核心校验（逻辑）：

   ```
   read(0, buf, 36)
   rbx = 0x358d0150819cf3c4
   for ecx in 0..35:
       bl = ror64(rbx, ecx) & 0xff
       if buf[ecx] ^ bl != blob[ecx]: fail     ; blob 位于 0x80481c3
   ```

   常量 `0x358d0150819cf3c4` 已在二进制中（文件偏移 163 = 0xA3）；`blob` 引用地址 `0x80481c3`。
4. 反推输入的公式：`buf[ecx] = blob[ecx] ^ (ror64(0x358d0150819cf3c4, ecx) & 0xff)`。
5. 在 Kali（<本机服务地址>，32 位 ELF compat 模式）上
   `echo <按上式推出的输入> | /tmp/x96` → 输出 **`Correct!`**（实跑验证通过）。
6. 格式差异：`task.json` 的 `flag_format` 写 `<历史答案已移除>`，实测真实 flag 外皮是**小写 `flag{}`**。
