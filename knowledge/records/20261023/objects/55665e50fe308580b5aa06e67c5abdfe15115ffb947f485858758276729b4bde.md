## 一、题型

**逐字符位掩码校验 crackme**。跟 level03/04（那两题是 `sscanf` 读 4 段数字 + 解方程组）
**完全不是一个套路**，别拿上一题的经验硬套。

- 二进制 14408 B，md5 `199e603f787daf744ef51e0050608201`（与 level01~04 都不同）
- key 长度 **20**，格式串 `%24s`
- 校验函数在 `0x4012f0`，成功返回 1 后 main 才去 `fopen("/flag")` 打印

## 二、★ 怎么一眼认出「逐字符掩码」这个套路

两个信号，都在**反汇编之前**就能看到：

1. **格式串是单个 `%24s`**（不是 `%5s-%5s-...` 那种多段）→ 不做分段解析
2. **导入表里没有 `sscanf` / `strtol` / `strcmp`**，只有
   `__printf_chk, fopen, perror, __isoc99_scanf, puts, fclose, fread`
   → 没有库函数做解析和比较，**校验必然是自己逐字节写的**

反汇编后的形态：对 `[rdi+0]`..`[rdi+0x13]` 每个字节做一串
`test al, 0xNN` / `and edx, 0xNN; cmp dl, 0xNN`，不满足就 `return 0`。
本质就是**二十组位约束**。

## 三、解法：写模拟器 + 按位暴力，不人肉读位

20 个字符、每个十几条位运算，手抄位约束必错（level03 手算 hex 已经连错两个的教训）。
改用两个新工具（都在 `tools\`）：

| 工具 | 作用 |
|---|---|
| `tools/elf_dis.py` | 本地 capstone 反汇编，**替代「每次去 Kali 跑 objdump」** |
| `tools/bitmask_crackme.py` | 迷你 x86 模拟器 + 按位暴力，直接出 key |

```bash
python tools/bitmask_crackme.py main --check 0x4012f0 --end 0x4016c0 --len 20 --show-candidates
```

输出每位候选**全部唯一**：

```

[10]Y [11]9 [12]y [13]3 [14]r [15]H [16]5 [17]8 [18]h [19]W

KEY = 7FCV5ROIA4Y9y3rH58hW
```

## 四、🔴 这轮踩到的四个坑（都是我自己埋的）

### 1. 反汇编**不能**在第一个 `ret` 停

校验函数里每个字符都有自己失败返回的 `ret`（`0x401300` 那条）。
按「读到第一个 ret 就停」只拿到 **8 条指令**，20 个字符块只认出 1 个。
→ 必须给 `--end`（下一个函数的起始地址）。

### 2. 🔴🔴 判断「走到第几位」不能看最后执行的地址

最常见的错法：拿模拟器最后执行的指令地址，看它落在哪个字符块的地址区间。

**错在哪**：失败分支 `0x401300: mov eax, r8d` / `0x401303: ret`
的地址**落在第 0 个字符块的地址区间里**（块 0 = `0x4012f0`~`0x401325`）。
于是「已经通过第 0 位、正在第 1 位失败」被判成「还在第 0 位」→ 每一位候选都是 0 个。

**正确做法**：跟踪 **读到过的最大字符偏移**（`movzx eax, byte ptr [rdi + N]` 里的 N）。
读到 N+1 就说明第 N 位过了。

### 3. `EI_CLASS` 是 `e_ident[4]`，不是 `[5]`

我写成 `b[5]` 报「只支持 64 位 ELF」。`[5]` 是 `EI_DATA`（字节序）。

现象像「命令不存在」。**这条规矩早就写进记忆了，还是漏了一次。**

## 六、可迁移性

- 同形态题目（`babyrev` 后续关卡、`babyc`、`babyvm`）直接复用
  `bitmask_crackme.py`，只需要三个参数：校验函数地址、key 长度、函数结束地址。

  本工具会打印每位候选数，若某位是 0 个或多个，就是假设不成立的信号，别硬信输出。
