# dataset · 训练数据采集

> **这是"让本地模型权重真正变强"唯一的数据来源。**
> 每解一道题，往这里追加三条样本（SFT / DPO / trace）。攒到 200~500 条就能跑 QLoRA。

## 为什么要现在就建

微调要几百条样本才有意义。**不按格式采集 = 以后全部重做。** 现在建，成本≈0。
知识库（`01`~`05`）是给"检索"用的；`dataset/` 是给"训练"用的，两者不重复。

## 本机可行性（2026-10-09 实测）

```
GPU   NVIDIA GeForce RTX 5060 Laptop · 8151 MiB · CUDA 12.8
结论  8 GB 够 QLoRA 微调 7B/8B（4-bit + gradient checkpointing）
      不够全参微调 7B；≤1.5B 可全参微调
```

## 三个文件

| 文件 | 格式 | 用途 |
|---|---|---|
| `sft.jsonl` | 多轮 chat（system/user/assistant/tool） | 监督微调：教"正确路径长什么样" |
| `dpo.jsonl` | `prompt` + `chosen` + `rejected` | 偏好对齐：教"两条路该选哪条" |
| `trace.jsonl` | 逐步工具调用记录 | Agent 轨迹训练 / 评测基线 |

**不把 jsonl 同步进 Obsidian** —— Obsidian 是阅读端，不是数据库。数据集只留本地。

## 统一 schema（`gm-ctf-v1`）

所有记录必带：

```json
{
  "schema": "gm-ctf-v1",
  "id": "<赛事>-<题目>",
  "task": "ctf-reverse | ctf-crypto | ctf-misc | ctf-pwn | ctf-web",
  "tags": ["dotnet", "aes-ecb", "lfsr", "z3"],
  "budget": {"max_tool_calls": 8, "max_seconds": 120},
  "outcome": "SOLVED | NOT_SOLVED",
  "flag": "flag{...} | null",
  "source": {"files": [{"name": "...", "size": 0, "sha256": "..."}]}
}
```

### `sft.jsonl` 追加

```json
{ "...公共字段...": "", "messages": [
  {"role": "system",    "content": "..."},
  {"role": "user",      "content": "..."},
  {"role": "assistant", "content": "...", "tool_calls": [{"name": "bash", "arguments": {"cmd": "..."}}]},
  {"role": "tool",      "name": "bash", "content": "..."}
]}
```

### `dpo.jsonl` 追加

```json
{ "...公共字段...": "",
  "prompt":   [ {"role": "system", "content": "..."}, {"role": "user", "content": "..."} ],
  "chosen":   [ {"role": "assistant", "content": "..."} ],
  "rejected": [ {"role": "assistant", "content": "..."} ],
  "why": "rejected 的失败原因（一句话，便于后续过滤/加权）"
}
```

### `trace.jsonl` 追加

```json
{ "...公共字段...": "", "steps": [
  {"n": 1, "phase": "分诊", "tool": "bash", "args": "...",
   "elapsed_s": 1.2, "verdict": "ok|fail|waste", "finding": "...",
   "why_waste": "（verdict=waste 时必填：这次调用本可以避免吗）"}
]}
```

> `verdict` 字段是刻意加的：**"浪费掉的调用"和"有效的调用"同样有价值** ——
> 它是 DPO 里 `rejected` 的原始依据，也是以后做"预算效率"评测的标签。

## 采集纪律

1. **同一道题，`chosen` 和 `rejected` 必须同题、同附件、同约束** —— 否则偏好对无效。
2. **失败路径也要存**。只存成功路径的模型学不会"什么时候不该动手"。
3. **`why_waste` 不能省**。它是以后做数据筛选和加权训练的抓手。
4. **flag 只在本地存**，不要同步到公开处。
5. 记录里**不要写"我猜"级别的结论**；未验证的假设放 `open_questions` 字段。

## 2026-10-10 Factor 采集

新增 1 条方法教学 SFT（非原始回复）与 1 条已留档部分 trace（非完整会话）。预算未统一设限，用 null 表示；已知局部时间分别记录。Qwen 的受限源码分析与主模型完整解题不满足同输入、同预算、同工具，未生成 DPO。诊断输入和失败原回复在战例 artifacts 中保留。
