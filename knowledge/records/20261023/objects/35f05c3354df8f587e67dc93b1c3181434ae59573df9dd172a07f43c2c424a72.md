## 一、给别的 AI 的话（整段复制）

```
你接下来可以调用一套本地 CTF 作战系统（CTF-OS），地址为 http://127.0.0.1:8787 。

接入方式（四选一，看你是什么客户端）：

1) 【推荐·零依赖】MCP stdio —— 你自己拉起进程，不需要任何服务在跑：
   {"mcpServers":{"ctf-os":{
     "command":"[USER_HOME]\\.workbuddy\\binaries\\python\\envs\\default\\Scripts\\python.exe",
     "args":["[CTF_ROOT]\\tools\\ctf_os.py","--stdio"],
     "cwd":"[CTF_ROOT]\\tools"}}}
   实测：initialize / tools/list / tools/call 可用；2026-10-12 新版注册 51 个工具。

2) 【零配置】直接跑命令行 —— 任何能执行 shell 的 agent 都能用，连 MCP 都不用配：
   python [CTF_ROOT]\tools\ctf_os.py --once math_gcd --args values=48,60
   → {"ok": true, "result": {"result": 12}, ...}
   接口自检：python [CTF_ROOT]\tools\ctf_os.py --selftest
   实际依赖体检：python [CTF_ROOT]\tools\ctf_os.py --doctor
   完整清单用 MCP tools/list；当前 51 个是注册数量，不能理解为每项已功能验收。

3) MCP over HTTP：指向 http://127.0.0.1:8787/mcp （**需要服务已启动**）
4) REST：POST http://127.0.0.1:8787/call ，body 形如
   {"tool":"crypto_shared_factors","args":{"numbers":[15,25,35]}}
   下面三种写法服务器都认，随便挑一种：
   - {"tool":"math_gcd","args":{"a":8051,"b":8633}}
   - {"name":"math_gcd","args":{"values":[8051,8633]}}
   - POST /call/math_gcd ，body 直接写 {"a":8051,"b":8633}

报错是自解释的：参数名写错会回给你「缺少参数 'xxx' + 该工具的参数 + 示例」；
工具名写错会回全部可用工具清单。照着改一次就能对。
执行失败：ok=false；CLI 返回非零退出码，MCP isError=true。
每次调用返回 evidence_path；CLI/MCP/HTTP 均记录本地审计。

先做这两步了解能力：
- GET http://127.0.0.1:8787/tools   看全部工具及参数 schema
- GET http://127.0.0.1:8787/status  看当前装备是否在线

你可用的能力分四类：
- 解题：数论/密码（gcd、模幂、模逆、多模数共享因子、RSA 解密）、
  编码（hex/base64/ROT/大整数转换）、GameBoy ROM 逆向、XOR 爆破、
  flag 格式校验
- 安全工具：Kali 上的 file/strings/binwalk/radare2/objdump，
  以及 nmap/hashcat/sqlmap（危险类）；本机的 sqlmap/ffuf/gdb/objdump
- 装备运维：查 Muteki 状态、体检上游模型、派题给 Muteki、查 run 日志死因
- 战例库：浏览已归档的题目与复盘

重要约定：
1. 标 dangerous 的工具必须带 confirm:true，否则会被拒绝。
   危险工具：muteki_dispatch、kali_run、kali_nmap、kali_hashcat、
   kali_sqlmap、local_sqlmap、local_ffuf、pc_run、pc_submit、win_debug_start、win_debug_call
2. Kali 是另一台机器（192.168.26.129），看不到本机文件。
   分析本机文件时用 local_file 参数，系统经统一桥上传并验证 SHA256，按文件摘要隔离。
   路径含空格时将整个参数加引号：--args "local_file=C:\目录 空格\sample.txt"
   可用 case 指定独立题号；执行保留客机日志，桥根据 VMX 查询当前 IP。
3. flag 相关的工具只做「格式校验」，不产出、不比对答案 —— flag 必须本地亲手跑出来。
4. 用 1) 或 2) 不需要任何服务在跑；用 3) 或 4) 才需要服务已启动
   —— 没启动就让管理员运行 [CTF_ROOT]\启动CTF系统-无窗口.vbs
5. Muteki 派单需要 prompt_file，默认一个尝试；已有未结束任务时拒绝重复派发。
   超时/停滞会请求停止；没有确认停止成功时不重派，避免重复消耗额度。
6. Windows PE 动态调试按需用 win_debug_*：先查状态、启动对应架构、查实际参数再调用。
   同一架构只分配给一位逆向 Worker 控制。通用调用需要 confirm:true，运行后重新查状态。
   未知附件先静态分析，动态运行使用合适虚拟机；本机调试器不是隔离沙箱。
```

## 三、前置条件（**这步不做，别人连不上**）

服务是普通进程，**不是系统服务**，需要人把它拉起来。两条路：

| 方式 | 操作 | 效果 |
|---|---|---|
| **推荐** | 双击 `[CTF_ROOT]\启动CTF系统-无窗口.vbs` | 无黑窗，服务常驻；已同时放进开机启动目录 |
| 调试用 | 双击 `[CTF_ROOT]\启动CTF系统.bat` | 有窗口，能看到日志；**窗口不能关**，关了就停 |

> 开机自启走的是用户级 Startup 目录（`…\Start Menu\Programs\Startup\CTF-OS.vbs`），
> **不需要管理员权限**，下次登录 Windows 自动拉起。

原因：这个环境里后台起的进程会随调用结束被回收，我没法替你常驻。

启动后验证：浏览器开 `http://127.0.0.1:8787/status`，有 JSON 回来就是活的。

**本轮修掉的 3 个 bug**（都是会让别人接进来就撞墙的）：

2. `/call` 只认 `{"tool":...}`，而文档和 MCP 侧都用 `name` —— **照文档调必报"未知工具: None"**，已改成都认，并补上 openapi 里承诺却没实现的 `POST /call/<工具名>` 路由。
3. 参数名写错回 `KeyError('candidate')` —— 外人看不懂，已改成把正确参数名和示例回给调用方。

## 六、鉴权与审计（2026-10-11 22:00 已补齐并实测）

| 场景 | 结果 |
|---|---|
| 本机 `127.0.0.1` 不带令牌 | ✅ 200（默认免密，不增加本机使用负担） |
| 局域网 IP 不带令牌 | ✅ 401 拒绝 |
| 局域网 IP + 正确令牌 | ✅ 200 |
| 局域网 IP + 错误令牌 | ✅ 401 |
| `?token=` 形式 | ✅ 200 |

令牌三种带法都认：`X-CTF-OS-Token` 头 / `?token=` / body 里 `token` 字段。

开令牌（对外时才需要）：
```
set CTF_OS_TOKEN=<你的令牌>
python ctf_os.py --host 0.0.0.0 --port 8787 --audit [CTF_ROOT]\logs\audit.jsonl
```
`python ctf_os.py --make-token` 可以生成一个随机令牌。

审计默认开启（启动器已带 `--audit`），落 `logs\audit.jsonl`，
每条记 `时间/来源IP/工具/参数/是否成功/耗时`；
**参数里的 key/token/password 等字段自动打成 `***REDACTED***`**。
