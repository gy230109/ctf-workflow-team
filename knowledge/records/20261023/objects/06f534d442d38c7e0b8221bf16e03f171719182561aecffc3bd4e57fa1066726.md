## 5. 已验证事实

1. **外部独立复算**：Python 按还原算法正向重算 `transform(flag)`，与二进制内
   expected（0x6280 起 32 字节）**逐字节一致**（`06751947…b11f3c`）。
2. **真机复现**：Kali（192.168.26.129）gdb 跟踪子进程，把候选 flag 写进 .bss 后
   直接调用二进制里的真实 `func_3580(buf, 29)`，返回值 **1**；换错误输入返回 **0**。
   （调用点为伪造栈帧，校验代码本身 100% 真实。）
3. 密钥表常数取自文件 0x6010，S 盒取自 0x6130，expected 取自 0x6280——均在原始附件里反查命中。

## 6. 这道题的坑

1. **父进程的 OK/No 是诱饵且逻辑反转**：`strncmp(buf, "flag{maybe_you_are_wrong}", 25)==0`
   → 打印 `OK!`；否则 `No!`。看到 `OK!` 别激动，那恰恰说明你输的是诱饵。
2. **`rm -rf --no-preserve-root /` 是恐吓但别赌**：`do_rm`(0x31e0) 由子进程
   `PTRACE_SETREGS` 把父进程 RIP 改过去触发。触发条件挂在 `wait()` 退出码 4 上，
   而子进程从不 fork，`wait()` 恒失败——分析上不可达；**跑原二进制前仍建议先把
   `do_rm` 入口 patch 成 `exit(0)`**（本次所有真机运行均用补丁版）。
3. **子进程从父进程内存偷输入**：`PTRACE_PEEKDATA` 读 `regs.rdi` 处 29 字节。
   用 gdb/strace 挂父进程会直接破坏这条链（ATTACH EPERM → `Error1` → 子进程退出）。
4. **OLLVM CFF 满屏伪分支**：按「状态变量 `-0x12c(%rbp)` + `sub $imm` + `je`」
   三段式过滤，再把 `.bss` 假条件块（`(x-1)*x&1==0 || y<10`）整块删掉，才看得见数据流。
5. **输出取 `w[32..35]` 而不是 `w[0..3]`**：少看这一步会以为变换是恒等的，直接卡死。
6. **PIE + `starti` 停在 ld-linux**：动态 PIE 的入口不是程序 `_start`；
   用「首个 PLT 调用的返回地址 − 调用点偏移」反推加载基址最稳。

## 8. 复现要点（方法，非留档脚本）

```python
SBOX = data[0x6130:0x6230]                      # 256 字节
T    = [qword(0x6010+8*i) for i in range(36)]   # 密钥表常数
KEY  = data[0x6270:0x6280]                      # 0123456789abcdef×2
EXP  = data[0x6280:0x62a0]                      # 32 字节 expected

ROL = lambda a,k: ((a<<k) ^ (a>>(32-k))) & (2**64-1)
def mix(x, rots):                               # be32 → S盒 → be32 → ROL 混合
    a = int.from_bytes(bytes(SBOX[(x>>s)&0xff] for s in (24,16,8,0)),'big')
    r = a
    for k in rots: r ^= ROL(a,k)
    return r

q = [be32(KEY[4*i:4*i+4]) ^ T[i] for i in range(4)]
for i in range(32): q.append(q[i] ^ mix(q[i+1]^q[i+2]^q[i+3]^T[i+4], (13,23)))

def block_fwd(B):                               # 16 字节 → 16 字节
    w = [be32(B[4*i:4*i+4]) for i in range(4)] + [0]*32
    for i in range(32): w[i+4] = w[i] ^ mix(w[i+1]^w[i+2]^w[i+3]^q[i+4], (2,10,18,24))
    return b''.join((w[35-j]&0xffffffff).to_bytes(4,'big') for j in range(4))

def block_inv(E):                               # 反向：只跟低 32 位走
    L = [0]*36
    L[32],L[33],L[34],L[35] = be32(E[12:]),be32(E[8:12]),be32(E[4:8]),be32(E[:4])
    for i in range(31,-1,-1):
        L[i] = L[i+4] ^ (mix(L[i+1]^L[i+2]^L[i+3]^q[i+4],(2,10,18,24)) & 0xffffffff)
    return b''.join(L[k].to_bytes(4,'big') for k in range(4))

flag = block_inv(EXP[:16]) + block_inv(EXP[16:])[:13]     # 29 字节
assert block_fwd(flag[:16]) + block_fwd(flag[16:]+b'\0'*3) == EXP
```

真机复现（安全补丁版）：`do_rm` 入口(0x31e0) → `exit(0)`；gdb
`set follow-fork-mode child` → 断 child 首个 `ptrace` PLT 调用反推 base →
写 flag 进 .bss(0x80c0) → 伪造栈帧调 `func_3580(buf,29)` → 断 0x4b8d 读 `$eax`。

## 9. 复盘：可复用的判断

| 触发信号 | 含义 | 动作 |
|---|---|---|
| ELF  stripped + OLLVM 注释 + ptrace/fork 导入 | 反调试 + CFL 混淆 | 别硬跑；先 objdump 全量 + 写 CFF 过滤器剥伪分支 |
| 二进制同时存在「诱饵 flag 串」和「另一套比较逻辑」 | 父进程逻辑是假的 | 找 fork/execve，真校验大概率在子进程 |
| 子进程 PEEK 父进程内存 | 输入被"隔进程"偷走 | 跟踪时只能挂子进程；挂父进程会 EPERM 破坏链路 |
| rodata 里有 256 字节表 + 一串 qword 常数 + 32 字节随机块 | S 盒 + 密钥表 + expected | 按「be32→S盒→be32→ROL」模式还原混合函数 |
| 分组变换输出"看似恒等" | 输出取的可能是扩展后的 word | 核对 unpack 的栈偏移，别默认 w[0..3] |

## 11. 收尾三问

1. **触发信号**： stripped PIE + OLLVM + fork/ptrace + 恐吓串 → 默认"父进程一切都是戏"，
   真逻辑去子进程找；输入来源优先怀疑 `PTRACE_PEEKDATA` 偷父进程内存。
2. **可迁移性**：「S 盒 + ROL 混合 + qword 密钥表 + 分组变换」是 OLLVM 题常见自定义密码；
   还原后**反向递推**比正推爆破便宜无数倍（G/F 只吃低 32 位，低 32 位序列自洽）。
3. **边界 / 失败分支**：若 expected 长度不是 16 的倍数（输入不足一组），补零规则要按
   `16 - len%16` 算；若变换带组间链式（CBC 式），反向递推要从后往前逐组解；
   真机复现时挂错进程（父 vs 子）会得到假阴性——先分清谁是真校验方。
