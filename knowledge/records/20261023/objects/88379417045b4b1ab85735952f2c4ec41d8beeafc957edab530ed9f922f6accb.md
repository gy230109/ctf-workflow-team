## 一、题型

crackme。二进制里没有 flag，要推出 key 喂进去，程序才去读 `/flag` 打印。

校验段在 `0x401310` 起：`sscanf` 读 4 段 → `strtol` 转成 a/b/c/d → 校验方程组。

## 二、★ 第一步必须先读格式串（这题的全部坑都在这）

格式串在 `.rodata` 的 `0x402041`，**静态 ELF 直接对应文件偏移 `0x2041`**：

```python
b = open('main','rb').read()
print(b[0x2041:0x2041+32])
# b'%5s-%5s-%5s-%5s\x00%24s\x00Good job! Go get yo'
```

**`%5s-%5s-%5s-%5s`** —— 三段信息：

1. 分隔符是 **`-`**（短横线），不是空格
2. 每段 **最多 5 字符** → a/b/c/d 都必须是 ≤5 位的数
3. 共 4 段

🔴 **不看格式串就会解出"数学上对、输入上错"的答案**。
我第一遍假设空格分隔、且没加 5 位约束，算出 `c=237911356`（9 位），
喂进去被 `%5s` 截断 → `Wrong key`，白折腾一轮。

## 三、方程组

```
(1) a*b + c - d           = 0x340fe872
(2) b - a                 = 0x5ee9
(3) d - 5*c               = 0xfffa3a38   ← 按有符号 32 位读
(4) (d + b) mod 100000    = 0x40d3
```

解（加 5 位约束后唯一）：

```
a = 19805
b = 44102
c = 90161
d = 72493
输入：19805-44102-90161-72493
```

## 四、🔴🔴 最大的教训：手算 hex 常量必错

我第一遍手算，连错两个：

| 常量 | 我手算（错） | Python 实算（对） |
|---|---|---|
| `0x5ee9` | 24313 | **24297** |
| `0xfffa3a38` | -396744 | **-378312** |

带错值去解方程组，得到的是**另一个"自洽但错误"的解**
（`32262 56559 237911356 1189160036`），而且它居然能通过我自己的复核
（因为我用错误的常量去复核）——**自我验证对上了，但题是错的**。

**规矩：所有 hex → 十进制一律用 Python，禁止心算：**

```python
import struct
signed = struct.unpack('<i', struct.pack('<I', 0xfffa3a38))[0]   # -378312
print(0x5ee9)                                                    # 24297
```

## 五、其他坑

1. **`--stdin` 值带空格/特殊字符必须加引号**：
   `stdin=32262 56559 ...` 不加引号只传进去第一个数，程序读到不完整输入 → Wrong key，
   现象像"解错了"，其实是参数没传全。
2. **先本地解方程再进容器**：纯数论，本地 Python 搜一遍出解，比反复进容器快得多。
3. **并发抢容器**：pull 完准备验证时容器已被切到别的题（同一账号只有一个活跃容器）。
   多 agent 并行跑 pwn.college 会互相破坏。

## 六、可迁移性

- 同类 crackme（`babyrev` 系列、`babyc`、`babyvm`）通用打法：
  **① 读格式串定输入约束 → ② 反汇编提常量 → ③ Python 精确换算 → ④ 本地解方程 → ⑤ 进容器验证**
- 顺序不能反：先看格式串，再看常量。
