# 解题工作流 Skill：`ctf-orchestrator`

2026-10-10 把这套工作流固化成了可分发给别人用的 skill。

- **安装位置**：`[USER_HOME]\.workbuddy\skills\ctf-orchestrator\`
- **分发包**：`[USER_HOME]\.workbuddy\skills\ctf-orchestrator.zip`（解压到别人机器的 `~/.workbuddy/skills/`）

## 设计要点

### 1. 模型管判断，工具管干活（最关键）

**skill 不绑定任何模型。** 谁当"脑子"都行——WorkBuddy、豆包、GPT、本地开源模型。

| 角色 | 负责 | 不负责 |
|---|---|---|
| 脑子（任意模型） | 读题、判断、拆步、派单、验收 | 确定性计算 |
| 手（工具节点） | 执行确定性计算并返回可验证结果 | 判断下一步干什么 |

### 2. 它是循环，不是流水线

```
读题 → 判断这步派谁 → 工具执行 → 拿结果 → 再判断下一步派谁 → ……
```

每一步都重新做派单决策，上一轮结果会改变下一轮的判断。

### 3. 主阶梯只有三个工具，第二模型不在里面

| 级 | 节点 | 说明 |
|---|---|---|
| 0 | 本地 Python / z3 | 大多数题解决在这一层 |
| 1 | REA | .NET / IL / managed |
| 2 | Kali | hashcat / 算力 / Linux 工具链 |

**第二模型被挪出主阶梯，降级为「旁路参谋」，默认关闭。** 三条理由：

1. **它算不了任何东西**——没有确定性计算能力，只能给意见。放在阶梯里是概念错误。
2. **实测只有一半正确率**——答对过「多个模数先查公因子」，答错过 gdb 下 SUID 读不到 /flag 的真因（答权限，真因是 ptrace 剥掉 SUID）。
3. **部署成本不划算**——别人机器上要 4.7GB 下载 + 配代理 + Ollama 常驻，换回这些不值。

> **给别人配 skill 时，本地模型这一项直接跳过。** 最小可用集 = SKILL.md + triage.py + 本地 Python。

### 3.5 靶场是另一类节点，不是算力节点

老板追问「别人电脑上怎么操作 pwn.college 那个网站」——这暴露了一个结构性遗漏：
**靶场根本不该和算力节点混在一起。**

| | 算力节点 | 靶场节点 |
|---|---|---|
| 干什么 | 执行计算，返回可验证结果 | **不出结果**——出题、给环境、判答案 |
| 可替代 | 能换 | 不可替代，题在它那 |

靶场同时是三种能力：**题源 / 执行环境 / 验收方**。

**顺带纠正了一个之前没分层清楚的东西 —— 验收层级：**

```
服务端返回 solved    ← 终局，最强信号
        ↑
本地三重校验          ← 拿不到服务端判定时的下位替代
```

之前把三重校验当"质量红线、没有例外"是**说重了**。
它的真实位置是：提交前给自己信心，以及**不能提交时**（离线题/只有附件）的唯一手段。
**能提交就提交，服务端说 solved 才算真解出来。**

### 3.6 顺手把 pc_flow.py 参数化了

它原本把两条绝对路径写死在代码里（`[CTF_ROOT]`、桥接目录），**根本没法分发**。
现已改成环境变量可覆盖：

| 变量 | 默认（本机） |
|---|---|
| `CTF_KB` | `[CTF_ROOT]` |
| `CTF_KALI_BRIDGE` | 本机桥接目录 |

换机器**不要改代码**，设环境变量即可。`pc_lib.py` 本来就用用户目录，无需改。

### 3.7 安全红线

skill 目录要打包成 zip 发出去，所以**账号 / cookie / token / SSH 私钥一律不许写进去**。
已做分发前自查：包内除安全提示自身外无命中。

## 质量红线（写进 skill 了）

任何 flag 进报告前必须三重校验：
1. **解唯一性** —— 搜索空间里只有这一个候选
2. **正推复算** —— 从答案正向跑一遍，与题面给的完全一致
3. **常量溯源** —— 魔数能在原始文件里定位（防「源码是诱饵」）

战例报告必须分区：已验证事实 / 未验证假设 / 未完成步骤。

## 开发过程中被测试抓出的 3 个 bug

1. **`nodes.py` 先替换再解析 JSON** → Windows 路径的反斜杠（`C:\Users`）被当成转义，
   直接 `JSONDecodeError`。修：**先 `json.loads`，再递归替换**。
2. **`triage.py` 用 str 正则扫 bytes** → `TypeError`。修：另备一份 bytes 版正则。
3. **`nodes.json` 里 `${PY}` 那层间接引用根本没生效**（`vars` 段没被实现），
   导致本地 Python 节点探测不到。修：去掉间接层，直接用 `${CTF_PY:python}`。

**教训：这三个都是"跑一遍真数据"才暴露的，静态看代码看不出来。**
