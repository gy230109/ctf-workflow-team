## 放在系统中的位置

| 部件 | 职责 | 何时使用 |
|---|---|---|
| 主 agent / WorkBuddy / Muteki | 分析题面、提出假设、安排步骤、读取证据 | 统筹各题型 |
| **REA（Ghidra 12.1.4）** | 生成的**静态**逆向分析：原生 PE 概览、反编译、函数、交叉引用、字符串；.NET 托管元数据与成员清单 | 需要伪代码 / 结构化静态证据时 |
| x64dbg + MCP | Windows 原生 x86/x64 PE **动态**调试：断点、单步、寄存器、内存、模块 | 静态分析不足、需要运行时证据时 |
| HackTricks | 检索技术原文和适用条件 | 根据现有证据查资料 |
| Kali + GDB/Ghidra/jadx/Sage | Linux 动态调试、通用静态分析、Android 逆向、数学计算 | 按题目格式与执行环境选择 |
| CTF-OS | 对外统一工具入口、参数校验、确认和证据归档 | 所有 agent 复用同一入口 |

REA 负责静态、x64dbg 负责动态，两者互补：先用 REA 拿结构、字符串、函数与调用关系，再对关键地址下断点做动态确认。

### 本次发现的上游差异

- Ghidra provider **没有远程模式**：必须本机安装且带匹配的原生 decompiler，无法直接复用 Kali 上的 Ghidra。
- Windows Ghidra 属上游**实验性 P0**（`docs/windows-ghidra-p0.md`）：只读、仅限本机 NTFS 上的原生 x86/x86-64 PE 应用。
- `--format json` 输出经 PowerShell `Out-File` 会带 BOM；解析前需去 BOM。

## 2026-10-12 晚：native 补验（Ghidra 后端实测通）★ 本轮新增

**结论先行**：§「未验证」里"x86 PE 原生分析"与"静态+动态联动"两条，本轮**已用同一样本验掉**。
`rea_status` → `ghidra: available`（6.2s）；`rea_run command=inspect` / `command=function` 对本机 x86 PE
`exit_code:0`（38~42s），真实产出段表、函数边界、汇编与 Ghidra 伪码。

| 项 | 实测值 |
|---|---|
| 引擎 | `rea-agents@6.4.0` + Ghidra 12.1.4 + JDK 21.0.11.10 |
| 样本 | `环境/验收/x64dbg-x32-20261012/fixture/probe32.exe`（与 x64dbg 补验**同一个**） |
| inspect | `pe` / `x86`，6 段（`0x400000`起），`procedure_count=2` |
| function `0x401000` | 汇编 `MOV EAX,[ESP+4]` / `ADD EAX,0x11` / `MOV [0x402000],EAX` / `RET`；伪码 `_DAT_00402000 = param_1 + 0x11;` |
| caller | `start` @ `0x40100d` |

**🔴 静态/动态地址换算（本轮最重要产出）**：
REA 给**文件地址**，x64dbg 给**运行时地址**。
`运行地址 = ASLR基址 + RVA`，`RVA = 文件VA − ImageBase`。
实证：REA 说 `start@0x40100d`（ImageBase `0x400000`）；x64dbg 实测主模块基址 `0xE00000`、
`entry_va = 0xE0100D = 0xE00000 + 0x100D`。x64dbg 单步读到的 `83 C0 11` 与 REA 伪码 `+ 0x11` 是同一件事。
→ 打法：REA 静态定位关键函数（拿文件 VA）→ 减 ImageBase 得 RVA → 加 ASLR 基址 → x64dbg 下断点。

**🔴 服务必须由计划任务托管（新发现）**：
用 `Start-Process` 起的 CTF-OS 会随调用结束被回收，端口直接消失（实测进程消失、`8787` 不再 LISTENING）。
已建计划任务 **`CTF-OS-常驻`**（`Register-ScheduledTask`，`ExecutionTimeLimit=0`、`MultipleInstances=IgnoreNew`、
`RestartCount=3`），进程跨多次调用稳定存活。开机自启仍由 `Startup\CTF-OS.vbs` 负责。
`wscript.exe` 被本机安全策略当 LOLBin 拦截，**不要用它起服务**。

**🔴 curl 必须加 `--noproxy '*'`**：本机代理 `127.0.0.1:12001` 会让 `curl http://127.0.0.1:8787` 直接返回空，
现象是"服务没起"，实际是走了代理。判活要先 `netstat -ano | grep 8787`。

**🔴 真实签名藏在报错文本里**：`rea function` 的参数形态（`<path> [address]`）不是从 `--help` 拿到的，
而是 `function --help` 触发 `REA 输出不是 JSON` 报错时，错误消息里带着完整 Usage。→ 猜参数会白跑一轮。
