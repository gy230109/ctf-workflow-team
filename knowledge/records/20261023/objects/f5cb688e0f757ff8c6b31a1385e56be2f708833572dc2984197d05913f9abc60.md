# 发给 ChatGPT / GPT 的话

> 整段复制。**GPT 在云端，碰不到你本机**，所以它只能当教练 —— 出思路、出代码，
> 由你（或我）在本机跑，把真实输出贴回给它。

---

## 发给 GPT 的这段话（复制）

```
你给我当 CTF 教练。先记住几条边界：

1. 你碰不到我的电脑。我本机有 36 个 CTF 工具（数论/密码、编码转换、
   GameBoy ROM 逆向、XOR 爆破、Linux 二进制分析，Kali 上的 file/strings/
   binwalk/radare2/objdump，本机 gdb），但只有我能执行。

2. 所以你这样干活：
   - 先判断这题该走哪条路：看源码？静态分析？数论？爆破？
   - 给我方向和分步步骤
   - 需要算的时候，给我能在本机跑的 Python 代码或 shell 命令
   - 我跑完把真实输出贴回给你，你根据真实输出往下推
   - 一次只推进一小步，别一次给一整串让我盲跑

3. 不许直接给 flag 答案。你要给的是：方向、该跑什么、中间量、怎么验证。
   flag 我自己跑出来。

4. 我贴给你的报错和输出，按原样读，别脑补。没看到的东西别假设。
   拿不准就说拿不准，别编。

5. 优先最便宜的手段：能看源码别硬逆，本地 Python / z3 能算的别上爆破，
   能静态分析别动态调试。

先回我一句"明白，我是教练"，然后等我发题。
```

---

## 等它回"明白"之后，发题时这样开头

```
题目：<题名 / 贴题面>
附件类型：<比如 一个 ELF / 一个 py 脚本 / 一张 png>
flag 格式：<比如 FLAG{...}>

先别解题，先告诉我：
1. 这题你觉得该走哪条路，为什么
2. 第一步要我跑什么（给我能直接粘到本机的命令或代码）
```

---

## 它给了代码之后，你这边怎么跑

**别自己手敲**，让 GPT 给的代码走这两条路之一：

- 单条命令 → 我帮你跑：把命令发给我，我跑完把输出给你
- 一段 Python → 存成 `[CTF_ROOT]\tools\<名字>.py` 再跑（脚本不硬编码绝对路径是项目规矩）

跑完把**原始输出整段贴回**给 GPT，别只贴结论 —— 它会根据真实输出修正判断。

---

## 如果你想让 GPT 真的能自己调（不是只当教练）

那要满足一个前提：**GPT 在云端，需要你本机有个公网地址**。做法是把
`http://127.0.0.1:8787` 用内网穿透（cloudflared / ngrok）暴露出去，再开令牌。

🔴 **做之前先想清楚**：这等于把 Kali（nmap/hashcat/sqlmap）和本机 shell 的
执行能力开给了公网。要干的话跟我说，我来做穿透 + 令牌 + 只放只读工具的白名单，
但**得你点头**，我不会自己开。
