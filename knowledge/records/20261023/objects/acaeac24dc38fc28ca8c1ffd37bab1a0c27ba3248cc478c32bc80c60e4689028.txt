这是一道 CTF 比赛题（类别：杂项 + 逆向混合）。工作目录里有三个附件：

- game.gb  —— 32768 字节的 Game Boy ROM
- kun.mp3  —— 128 kbps / 44.1 kHz 立体声，约 222.9 秒
- man.mp3  —— 同格式，约 228.2 秒

请自主分析并找出 flag。

===== 已确认的客观事实（可直接采用，不必重复验证）=====

1. game.gb 是结构合法的 Game Boy ROM：
   - 0x0104-0x0133 的任天堂 Logo 完整正确；
   - 头部校验 0x014D = 0xCC，按 "X = X - byte - 1" 复算一致；
   - 全局校验 0x014E = 0x830E，复算一致 —— 说明整个文件没有被事后改动过。
   - title @0x0134 = "GAME"；cart_type @0x0147 = 0x00 (ROM ONLY)；
     rom_size @0x0148 = 0x00 (32KB / 2 bank)；entry @0x0100 = 00 C3 50 01 (JP 0150h)。

2. ROM 的 bank1（偏移 0x4000-0x7FFF，16384 字节）整块是 0xFF，完全未使用。
   全部内容都在 0x0000-0x3FFF 这 16 KB 内。
   其中 0x0800-0x0A00 附近存在可辨认的字体图块（能看出 0-9 A B C D E F L 等字形）；
   0x0D40 之后是一大段高度重复的 7-8 字节模式，循环出现：
       22 72 2B 5E 23 56 3E   ("r+^#V>")
       32 2B 5E 23 56 23 6E 26 ("2+^#V#n&")
   该区域一直延续到接近 0x3400，尾部收成台阶状，之后转回 0xFF。

3. 两个 mp3 的 ID3v2.4 标签在文件偏移 138 处结束（syncsafe size = 128）。
   源文件元数据为 major_brand=mp42 / compatible_brands=isommp42 /
   Lavf56.25.101 / LAME3.99.5 —— 即由某个 MP4 抽出音轨后再编码。

4. kun.mp3 与 man.mp3 **不是同一段音频的微改**：
   两者从文件偏移 184 起就不再相同，同长度区间只有约 1.6% 的字节相同
   （接近随机基线 0.4%，加上帧头与尾部填充），因此逐字节 diff 没有意义。

5. kun.mp3 整段波形包络几乎恒定（每秒 RMS 稳定在 7000-11000，峰值 0.986 FS，
   过零率 13.8%）；man.mp3 前 6 秒是静音然后渐入（每秒 RMS 从 0 升到 4000+），
   更像一段正常的乐曲。

===== 环境 =====
容器内有 ffmpeg / ffprobe，也有 python3。可以自由安装或自行实现所需工具。

===== 建议方向（仅供参考，不要被这几条限制）=====
- 反汇编或模拟 game.gb，先搞清楚它到底在做什么（LR35902 指令集）。
- 检查 mp3 的帧结构里是否存在 ancillary data 或非音频负载，
  以及两个 mp3 在同一偏移上是否共享某种结构。
- 比较两段音频在时域/频域上的结构化差异。
- 重点看 ROM 里那段"重复的 7-8 字节模式"究竟是什么：数据表？图块？压缩流？
  还是被某种编码后的文本？
