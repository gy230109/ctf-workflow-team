## 3. 解题链路

```text
n11/n12 → 连分数 q11/q12 → 两组 p²q 因子 → 解出 m1、m2
inverse(m1,n2)/n2 → 连分数 → p2*q2 → 六次开根 → 解出 b
e3/b → inverse(e3/b,n3)/n3 → 连分数 → p3*q3 → 解出 flag
```

第一层 `n11=p11²*q11`、`n12=p12²*q12`，1792 位的两个大素数非常接近，512 位的小素数之比因此藏在模数比里。遍历 `n11/n12` 的收敛分数；仅接受分子/分母分别整除对应模数，且商是精确平方的候选。本题命中索引 **310（从 0 开始）**。恢复 `φ(p²q)=p(p−1)(q−1)`，分别解密 `c11,c12` 得到 `m1,m2`。

第二层 `N2=p2⁷*q2`，`m1*d1 ≡ 1 mod φ2`，`d1` 只有 672 位。取 `s=inverse(m1,N2)`，利用 `N2`、`φ2` 的公共因子 `p2⁶`，得到：

```text
s = d1 + t*p2⁶
s/N2 = t/(p2*q2) + d1/N2
```

实际 `gcd(t,p2*q2)=1` 且 `2*d1*(p2*q2)² < N2`，所以目标分数是收敛分数。本题索引 **558** 的分母为 `p2*q2`；`N2/(p2*q2)=p2⁶`，精确六次开根得因子。用 `e2=65537` 解密 `c2` 得到 672 位的 `b`。

第三层 `e3=inverse(a,φ3)*b`。核实 `e3 % b == 0` 后除掉 `b`，同样以 `inverse(e3/b,N3)/N3` 做连分数攻击；索引 **598** 恢复因子。最后核实 `gcd(e3,φ3)=1`，逆转完整指数 `e3` 得 flag。

这里无需格、Coppersmith 或 SMT。一般判据和失败分支见 [06-密码SOP](../../06-密码SOP-连分数与素数幂RSA.md)。

## 5. 已验证事实

1. 四个模数均满足留档因子的精确乘积；历史脚本输出索引 `310/558/598`。
2. `m1,m2` 分别为 4094/4093 位，`d1,d2,a,b` 均为 672 位；源码第二层的 `len(bin(N))==4096` 含 `0b`，实际 `n2` 为 4094 位。
3. `m1,m2,b,flag` 用原始指数重新加密，分别严格等于 `c11,c12,c2,c3`。
4. `proof-checks.json` 中三条 Legendre 界、两条余项恒等式、两条约分条件共七项全部为 true。
5. `gcd(e3,φ3)=1`。本题四个密文都是模数的单位；独立核验另用 Carmichael `λ(N)` 复算相同明文。
6. 本地回复因长度上限结束；原文未找到关键攻击路线。此结论只覆盖这次输入与参数，不能推出它不能解同类题。

## 10. 可复用的经验

| 触发线索 | 下次具体动作 | 验收条件 / 失败分支 |
|---|---|---|
| `p^r*q` | 先展开 φ 的公共素数幂因子 | 不直接套普通 `pq` RSA 的 φ |
| 两个大素数异常接近 | 比模数并遍历连分数 | 候选整除 + 精确幂 + 近似界；失败再判断约分/半收敛 |
| 小整数的逆作为下一层公开量 | 尝试再取模 N 的逆，整理余项 | 看有效分母 `pq`；不是只盯 N 的位数 |
| 指数等于“逆元乘 b” | 从上一层取 b，检查整除，再约简结构 | 最终仍检查完整指数与 φ 的 gcd |
| 题面出现很复杂的 delta | 先代入实际位数比较大小 | 本题 d 的接近约束太宽，不作为关键漏洞 |
| 本地模型只说“先分解 N” | 要求给出一个可检验关系或短脚本 | 下一步优先补知识检索，不无限重复同一提示 |
| Kali 空间/依赖紧张 | 优先标准库，结果写 JSON 再 fetch | 不为几次整数运算临时安装完整大工具链 |
