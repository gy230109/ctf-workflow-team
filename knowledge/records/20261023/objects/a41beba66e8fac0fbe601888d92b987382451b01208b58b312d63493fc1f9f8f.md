## 1. 职责切分（"二合一"不是把两份代码搅一起）

| 层 | 角色 | 干什么 |
|---|---|---|
| **A**（`pc_flow.py`） | **题库 + 环境 + 验收官** | 拿登录态、起挑战容器、捞 `/challenge`、**提交 flag 拿服务端 solved** |
| **B**（Muteki） | **解题大脑** | 只给题面与附件，自己决定怎么打 |
| **本脚本** | **胶水** | 把上面两件串起来（原来这根胶水是"我"） |

### 摸底时的关键发现
原以为"Muteki 够不到 pwn.college 挑战容器"是硬障碍。**查 `pc_flow.py` 源码发现 A 里早就有这一块**：

| 能力 | 子命令 | 说明 |
|---|---|---|
| 起容器 + 捞题 | `pull` | 启动 → 轮询 `/docker` → SFTP 捞 `/challenge` → manifest |
| **在挑战容器里执行** | **`run`** | `run_remote(cmd, timeout, stdin)` ← **B 拿不到的那一块，已造好** |
| 重算力 | `kali --script` | 上传脚本到 Kali 跑，取回产物 |
| **服务端验收** | `submit --flag` | 返回 `success/solved` |

→ **缺口不在"执行环境"，只在"让 Muteki 调的到这些入口"。**

## 2. ⚠️ 半自动模式的**能力边界**（必须如实说，不许吹）

Muteki **只能拿到静态附件**，**不能**交互式访问挑战容器。

| 题的类型 | 半自动能否解 | 例子 |
|---|---|---|
| 纯静态可解（算法、可逆变换、MD5 原像） | ✅ 能 | `flag0`（MD5）、`flag-1`（可逆变换） |
| 必须在容器里反复试（SUID、syscall、缓冲区） | ❌ 不能 | reversing-hell 多数模块 |

**这条边界已写进喂给 Muteki 的 prompt 里**（模板见脚本 `PROMPT_TMPL`），
并要求它"找不到就直说未解出，**不要编造**"。

要突破这条边界 → 得升级到**实时双向桥**（见 §6）。

## 3. 流程

```
[1/4] pc_flow.py pull --no-kali        起容器 + 捞题 + manifest
[2/4] 组 prompt -> 临时文件 -> muteki_client.py submit   派单，拿 run_id
[3/4] 盯守：SSE 收事件喂空转探针 + 每 20s 查 /api/runs 终态
[4/4] 拿到 flag -> pc_flow.py submit   服务端验收（唯一有效验收）
```

**停滞判定复用 `20-Muteki空转探针.md` 的 `Tracker`** —— 因为 `/api/runs` 的 `updated_at`
**区分不了空转**（空转时 blackboard 还在滚），必须看 `tool.start` 间隔。

## 4. 用法

```bash
# dry-run：只组装并打印 prompt，零副作用（不联网、不起容器）
python pc_x_muteki.py plan --dojo reversing-hell --module welcome --challenge flag2

# 全流程（会起容器 + 派单，消耗模型额度）
python pc_x_muteki.py go --dojo reversing-hell --module welcome --challenge flag2 --timeout 1500

# 题已拉过、只是重派
python pc_x_muteki.py go ... --no-pull
```

## 6. 何时升级到"实时双向桥"

半自动解不了的题（多数 reversing-hell）需要 Muteki **逐步**在容器里试。
那时要：A 起本地 HTTP 服务 → portproxy 放给 VM（照抄 `WorkBuddy2API` 的 `192.168.26.1:7863` 套路）
→ 暴露**受限的** `run` / `submit`（worker 仍拿不到 cookie）。

**判断依据**：半自动跑满 3–5 题后，看失败原因是"题需要交互"还是"Muteki 太弱"。
**前者才值得升级，后者升级也没用。**

---

## 7. 红线（不可让步）

- **cookie 只留在宿主 A 层**，worker 永远拿不到（等同账号权限）
- 不硬编码路径：`CTF_KB` / `CTF_MUTEKI_BASE` / `CTF_MUTEKI_PW_FILE` 均可覆盖
- Muteki 说未解出时，**不许替它编 flag**，如实记"未解出"
- 只有 `submit` 返回 `success` 才算解题 —— **服务端 solved > 任何本地自证**
