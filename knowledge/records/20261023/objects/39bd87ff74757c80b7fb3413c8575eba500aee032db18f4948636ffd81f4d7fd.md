# 给桌面上的 Trae 说的话

## 前提（不做这步，后面白说）

Trae **现在正在运行**，但它还没读过 MCP 配置（日志是空的）→ **先完全退出 Trae 再重新打开**。

退出要干净：任务栏右下角找到 Trae 图标退出，或任务管理器里把所有 `Trae CN.exe` 都结束掉，再重新打开。

配置我已经写好了，两个位置：
- `[USER_HOME]\.trae\mcp.json`（用户级，所有项目都能用）
- `[CTF_ROOT]\.trae\mcp.json`（项目级，打开强网杯大师目录时生效）

---

## 打开 Trae 后，先发这句（验证有没有接上）

```
你接了我本机的 CTF-OS 作战系统（MCP 服务器名 ctf-os，36 个工具）。
先调用 tools/list，把工具名报给我，确认你真的看到了。看不到就说看不到，别装。
```

**判据**：它如果能列出 `math_gcd`、`crypto_shared_factors`、`kali_file`、`gb_disasm` 这一串，就是接上了。

---

## 接上之后，发这段定规矩

```
我练 CTF，你当教练和工具手，按这几条来：

1. 危险工具 kali_nmap / kali_hashcat / kali_sqlmap / local_sqlmap /
   local_ffuf / kali_run / muteki_dispatch，调用时必须带 confirm:true，
   不带系统直接拒绝，别反复试。

2. Kali 是另一台机器（192.168.26.129），它看不到我本机的文件。
   要分析我本机文件时用 local_file 参数，系统会自动上传过去。

3. 不许直接给 flag 答案。你只给：方向提示、该调哪个工具、
   中间量、格式校验。flag 我自己跑出来。

4. 拿不准就说拿不准，别编。报错了把原始报错给我，别自己圆。

5. 优先用最便宜的手段：本地 Python / z3 能算的别上 Kali，
   能看源码的别硬逆。
```

---

## 如果 Trae 说看不到工具

按顺序查：

1. Trae 是不是真的重启了（任务管理器里 Trae 进程数归零过没有）
2. 设置里找 MCP / 工具 那一栏，看 `ctf-os` 在不在列表里 —— 有的客户端要手动点"启用"或"信任"
3. 手动验一下这条命令有没有输出（能出 JSON 就说明服务端没问题）：
   ```
   echo {"jsonrpc":"2.0","id":1,"method":"tools/list","params":{}} | python [CTF_ROOT]\tools\ctf_os.py --stdio
   ```
   第 3 步出 JSON 而 Trae 看不到 → 是 Trae 客户端的问题，不是我们系统的问题。
