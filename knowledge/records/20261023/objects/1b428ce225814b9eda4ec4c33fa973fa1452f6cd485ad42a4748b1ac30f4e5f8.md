# DUTCTF · Reverse · re1

> 方向：Reverse（Windows 原生 PE · 明文比对入门题）
> 附件：`re1.zip` → `re1.exe`（90624 字节，PE32 i386，MSVC 编译，sha256 `f8098f04d2eba80a0dc4a4dfe67b43268d92db3928bfe6d3958277766620d318`）
> 答题日期：2026-10-14。状态：**本机实机复现通过**

## 1. 结论

> **Flag：** `DUTCTF{We1c0met0DUTCTF}`

`main` 读入字符串后，**直接**与 `.rdata` 里的明文常量做 `strcmp`——没有任何算法、加密或变形。
题目自带提示语「这是一道很可爱很简单的逆向题呦」，属实。

## 2. 题面

只有一个 `re1.exe`，双击/命令行运行后提示输入 flag。无其他附件。

## 3. 解题链（怎么想出来的）

```
re1.zip → re1.exe（90624B）
  │ ① PE 头：MZ/PE ok，machine=0x14c（i386）、opt magic=0x10b（PE32）、CLR 目录 size=0 ⇒ 原生 32 位 PE，非 .NET
  │    区段正常（.text/.rdata/.data/.rsrc/.reloc），无壳
  │ ② 导入表：IsDebuggerPresent / CreateProcessA / LoadLibraryExW / GetProcAddress …
  │    ⚠️ 看着像反调试，其实是 **MSVC CRT 自带**（system("pause") 走 CreateProcessA、API 动态解析走 LoadLibrary+GetProcAddress）——**别被吓到**
  │ ③ 全量反汇编（objdump -d -M intel），沿 CRT 启动链找 main：
  │    入口 0x4014a5 → jmp 0x40132a（__scrt_common_main_seh）→ 0x401423 call 0x401000 = **main**
  │ ④ main @0x401000 逻辑：
  │      movdqu xmm0,[0x413e34] ; 16B 常量 → [ebp-0x44]
  │      movq   xmm0,[0x413e44] ; +8B
  │      打印 3 行提示 → call 0x4010d1(scanf "%s", &buf)
  │      内联 strcmp(buf, [ebp-0x44]) → 相等打印 0x413e90，否则 0x413e9c
  │ ⑤ dump .rdata 常量（RVA 0x13e34 → 文件偏移 0x13234）
  ▼
DUTCTF{We1c0met0DUTCTF}   （24 字符 = 16B + 8B 两次 xmm 加载）
```

## 5. 已验证事实

1. 期望常量就在 `.rdata` 0x413e34，**明文**：`DUTCTF{We1c0met0DUTCTF}`（24 字节，末尾 NUL 由 `mov WORD PTR [ebp-0x28], ax`（ax=0）写 2 字节补齐）。
2. 长度自洽：16 字节（xmm 一次）+ 8 字节（xmm 一次）= 24 字符，与字符串长度完全吻合。
3. **实机双向验证**：正确输入 → `flag get√`；错误输入 → 失败提示。非纸面推断。
4. 程序尾部 `system("pause")`，其输出「请按任意键继续. . .」在管道输入下立即返回，不影响判定。

## 6. 这道题的坑

1. **导入表虚张声势**：`IsDebuggerPresent`/`CreateProcessA`/`LoadLibraryExW`/`GetProcAddress` 全是 MSVC CRT 的常规实现（安全 cookie、`system()`、API 动态解析）。**先分辨"谁调的"再决定要不要跟**——查 IAT 引用点能快速定位是不是用户代码。
2. **main 不是入口**：入口 0x4014a5 只是 `__security_init_cookie` + 跳 CRT。要找 `call <main>`（0x401423），别从入口硬读。
3. **常量是拆开加载的**：字符串经 `movdqu`(16B) + `movq`(8B) 分两次搬入栈，dump 时长度要按 24 字节（别只看 16B）。

## 8. 复现要点（方法）

```bash
# 1) 判型：PE32 i386、CLR 目录为空 ⇒ 原生 PE
# 2) 全量反汇编
objdump -d -M intel re1.exe > full.asm
# 3) 沿 CRT 找 main：入口 → __scrt_common_main_seh → call <main>
# 4) 见 "movdqu xmm0,[0x413e34]" 这类常量搬运 ⇒ 直接 dump 该地址
# 5) RVA→文件偏移：off = sec.raw + (rva - sec.va)
# 6) 实机跑一遍：printf '<flag>\n' | ./re1.exe
```

## 9. 复盘：可复用的判断

| 触发信号 | 含义 | 动作 |
|---|---|---|
| PE 里导入 `IsDebuggerPresent`/`CreateProcessA` 但代码量小 | 多半是 CRT 自带，不是自定义反调试 | 用 IAT→调用点映射，看**调用者是不是用户函数**再决定 |
| main 里有 `movdqu/movq xmm0,[常量地址]` | 字符串被拆块搬到栈上 | 直接按地址 dump，注意总长 = 块长之和 |
| 看见 `call 0x4010d1` 且前面 push 了 `%s` 格式串 | msVCRT 的 scanf 包装 | 输入是字符串，校验紧随其后 |
| 一个 `strcmp` 内联比较后就分支打印成功/失败 | **明文比对题** | 不需要动调，dump 常量即解 |

## 11. 收尾三问

1. **触发信号**：小体积 Windows PE + 一堆反调试 API 导入 + 题面说"简单" → **先别动调，先找 main 里的明文比较**。
2. **可迁移性**：入门逆向题的通用秒杀顺序 = 判型（是否 .NET）→ 找 main（沿 CRT 调用链）→ 看常量搬运（xmm/memcpy）→ dump 字符串 → 实机验证。绝大多数"很简单的逆向题"死在第 3 步之前的过度分析上。
3. **边界 / 失败分支**：若常量不是明文（异或/编码），则退到跟进使用该常量的比较函数；若有反调试（本次为 CRT 假象），先用 IAT 调用点区分系统库与用户代码；若真被反调试（`IsDebuggerPresent` 在用户代码里且影响分支），再上 x64dbg 改标志位或 patch 跳转。
