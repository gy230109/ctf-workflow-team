## 五、二次取证：扒出字体表

### 5.1 真凶：tile 数据地址算错了

GB 的 tile 数据基址由 `LCDC(0xFF40)` 的 **bit4** 决定：

| LCDC.4 | 基址 | tile n 的 VRAM 地址 |
|---|---|---|
| 1 | 0x8000 | `0x8000 + n*16` |
| **0（本题，LCDC=0xC3）** | 0x8800（有符号） | `n<128` → **`0x9000 + n*16`**；`n>=128` → `0x8800 + (n-128)*16` |

用错基址会读到全 0 的空白 tile → 误判"字体没加载"。**这是本题最大的一个坑。**

### 5.2 实测字体表（标题画面与游戏画面一致）

| tile | 字符 | tile | 字符 |
|---|---|---|---|
| 0x41 | **P** | 0x4C–0x55 | **'0'–'9'** |
| 0x42 | **R** | 0x56 | **U** |
| 0x43 | **E** | 0x57 | **L** |
| 0x44 | **S** | 0x58 | **B** |
| 0x45 | **T** | 0x8A | **`{`** |
| 0x46 | **A** | 0x8B | **`}`** |
| 0x47–0x4B | 5 个抖动/明暗块 | | |

**自洽性验证（通过）**：标题 tilemap row31 = `65,66,67,68,68,00,00,68,69,70,66,69`
→ 按上表读 = `P R E S S _ _ S T A R T` ✅，与屏幕实拍一致。

## 六、最终定位与复现

### 6.1 门控条件（反汇编原文）

```
1C5E  LD HL,SP+6 / LD (HL),2Ah       ; 清 42 字节栈缓冲
1C89  DEC HL
1C8C  LD A,(HL)                       ; A = 来自 RAM 0xC0A2 的那个字节
1C8D  CP FFh                          ; carry 置位 <=> A < 0xFF
1C8F  DA 6B 1D   JP C,$1D6B           ; A<FF → 走 "RESULT/BEST"；A==FF → 落入下面的隐藏串
1C92  58 51 3E 8A 12                  ; LD E,B / LD D,C / LD A,$8A / LD (DE),A   → 先画 '{'
```

### 6.2 隐藏串本体（tile 索引，按绘制顺序）

```
8A 41 44 4C 4F 42 50 55 56 43 51 53 52 42 50 4E 4D 42 43 54 8B
{  P  S  0  3  R  4  9  U  E  5  7  6  R  4  2  1  R  E  8  }
```

### 6.3 三条独立复现路径（全部命中同一结果）

| 路径 | 做法 | 结果 |
|---|---|---|
| A 静态 | 线性解码 0x1BF8–0x1D58 的 `LD (HL),n` 立即数 | `{PS03R49UE576R421RE8}` |
| B 动态（改内存，**推荐/等价于官方题解**） | pyboy 实跑 + 注入 `0xC0A2=0xFF` | 屏幕显示 `{PS03R49UE576R421RE8}` ✅ |
| C 动态（改 ROM） | 把 0x1C8F 的 `DA 6B 1D` 改成 `00 00 00`（NOP 掉条件跳转） | 屏幕显示 `PS03R49UE576R421RE8` ✅ |

**B 与 C 互为交叉验证**：一个不动 ROM、一个不动内存，结果一致。

## 七、可复用的教训（写给下一次）

1. **「读不出来」≠「那里没东西」。** 地址基址、步长、字库映射，任一处假设错就得到假阴性。
2. **看到"疑似密文"先问：这是数据，还是指令的立即数？** 扫 `36 xx` 得到的字母串是伪影。
3. **静态解出字符串不算完 —— 必须动态跑一遍亲眼看到。** 本题里"解出来"和"真能看到"是两回事
   （要先满足 `[0xC0A2]==0xFF`，正常玩法永远到不了）。
4. **线性反汇编不能从固定地址一路扫到底** —— 撞上数据区就永久失步（实测得 0 段，假阴性）。
   用"模式扫描 + 间隔聚类"才稳。
5. **别用子串匹配去"找"东西**，先整块解码再读。本题的坑就是把 ASCII 当 tile 索引。
