## 一、题型：**cmov 链**

跟 level05（逐字符掩码 + 提前 return）**又是另一个套路**。
babyrev 每一关换一种生成方式，别指望一招吃到底。

- 二进制 14408 B，格式串同样是 `%24s`，key 长度同样 20
- `.text` 3061 B（level05 才 1669），校验函数 `0x4012f0` ~ `0x401c27`，695 条指令

**形态**：一条长长的 `if (cond) eax |= K`，末尾
```asm
0x401c0a: test byte ptr [rsp - 7], 0x10   ; s[1] 的 bit4
0x401c0f: je  0x401c1a                    ; 为 0 直接返回 0
0x401c14: test eax, eax
0x401c16: sete r8b                        ; 返回 (eax == 0)
```
→ **通过条件 = `eax == 0` 且 `s[1] & 0x10 != 0`**。

因为 `or` 只置位、不清位，**eax 想保持 0 就必须让每一个条件都不成立**。
于是整条链等价于一百多条「第 i 个字符的第 b 位必须是 0 / 1」的约束。

初值也是一条约束（用 `sbb` 技巧做的）：
```asm
0x401308: mov eax, r14d     ; r14 = s[0xa]
0x401314: and eax, 0x10
0x401324: cmp al, 1
0x40132f: sbb eax, eax      ; CF=1 -> eax=-1
0x40133a: and eax, 0x1b     ; -> 0x1b，若 bit4 为 1 则是 0
```

## 二、🔴 为什么必须忠实模拟，不能人肉读

这题最阴的地方：**寄存器复用取标志**。

```asm
0x40140f: and  r15d, 0x40     ; 取标志：r15 此时还是 s[0xf]
0x401413: mov  r15d, r11d     ; 立刻把 r15 覆盖成 s[0xe]（不影响标志）
0x401416: cmove eax, edx      ; 用的还是上一步 and 的标志
```
类似的还有 `and ebp,0x40` → `movzx ebp,[rdi+8]` → `cmove`、
`and esi,0x20` → `movzx esi,[rdi+3]` → `cmove`。

**一眼扫过去很容易把条件记到被覆盖后的那个字符身上** —— 差一个字符，
整串就废了，而且错得很隐蔽（解出自洽的错 key）。
→ 必须让模拟器按顺序忠实执行，别去"提炼"。

## 四、🔴🔴 这轮最值钱的教训：贪心会卡在「AND 型罚分」上

第一版我用 `罚分 = 触发数 + (通过 ? 0 : 1)` 做单翻贪心，**降到 1 就卡死**。

原因：那最后 1 分是**两个互不相干条件的 AND**——
`(初始 eax == 0)` 和 `(s[1] & 0x10 != 0)`，各占半分。
单独修好任一个，AND 仍然为假，罚分**一点不降** → 贪心看不到进步，两条都不敢动。

- s[1] = `'` = 0x27 → bit4 = 0（门闸没过）
- s[10] = `` ` `` = 0x60 → bit4 = 0（初值 eax = 0x1b）

**改法（已固化进工具）**：
1. **阶段一只优化「按位可分离」的那一半**（触发数），单翻就能收敛到 0；
2. **阶段二再做双位联合搜索**，把 AND 型的那 1 分一次修掉。

> 通用判据：**罚分项里只要出现 AND / OR 聚合，单翻贪心就会卡住。
> 先把可分离的部分榨干，剩下的一定是少数几个"联合才有效"的位。**

## 五、两关对照

| | level05 | level06 |
|---|---|---|
| 形态 | 逐字符 `test/cmp` + **提前 return 0** | 一整条 `cmov` OR 链，**末尾才判** |
| 约束是否按位独立 | 是（且逐字符提前退出） | 是（但**没有**提前退出） |
| 进度度量 | 读到过的最大字符偏移 | 触发了多少个条件 |
| 解法 | `--mode block` 按位推进暴力 | `--mode greedy` 按位贪心 + 双位补刀 |

## 六、可迁移性

- 先**看格式串和导入表**判断题型（level05 那篇写了信号），再选 `--mode`。
- 换 `--mode` 只需要三个参数：校验函数起止地址、key 长度。
- 工具遇到没实现的指令会**直接抛异常而不是跳过** —— 这是故意的：
  悄悄跳过会得到一个"看起来自洽"的错解，比崩掉危险得多。
