## 1. 结论

> **Flag：** `alictf{Y0vAr3TimerMa3te7}`

`MainActivity` 用定时器等 200000 秒，把累加出来的 `k` 交给 native `stringFromJNI2(k)`，
返回 `Y0vAr3TimerMa3te7`（17 字符，语义 = "You are Timer Master"）。

- Java 侧累加：`k = 100·π(200000) − (200000−π(200000)) = 100×17984 − 182016 = `**1616384**
- native 侧：用 **double 浮点混淆**逐字节生成这 17 个字符（`buf[i] = (int)(X / c_i) & 0xff` 形式）

## 2. 题面

APK 只有一个 MainActivity，界面显示倒计时；核心是 `public native String stringFromJNI2(int i);`
（`System.loadLibrary("lhm")`），flag 拼装：`"alictf{" + stringFromJNI2(k) + "}"`。

```java
int beg = ((int)(System.currentTimeMillis()/1000)) + 200000;
int k = 0;
// 定时器每轮（稳定后恰好 1s 一次）：
//   if (beg - now <= 0)  tv2.setText("alictf{" + stringFromJNI2(k) + "}");
//   if (is2(beg - now))  k += 100;  else  k--;      // is2 = 素性判定
// 说明：t = 1500 - (ms % 1000) ⇒ 每次调用后 ms%1000 恒为 500 ⇒ 之后间隔精确 1000ms
```

## 3. 解题链（怎么想出来的）

```

  │ ① 解包：classes.dex + resources.arsc + **lib/armeabi/liblhm.so** ⇒ 逻辑在 native
  │ ② manifest：package=net.bluelotus.tomorrow.easyandroid，LAUNCHER=MainActivity
  │ ③ jadx 反编译 → MainActivity：定时器 + is2(素数) 累加 k，200000 秒后拼 flag
  │ ④ 先算 k（纯 Python，与 native 无关）：
  │      n 取 200000…1，is2(n) 为真 → +100，否则 -1
  │      k = 100·π(200000) − (200000 − π(200000)) ；π(200000)=17984 ⇒ **k=1616384**
  │ ⑤ 转 native：从 APK 提取 liblhm.so（ELF 32-bit ARM）
  │      readelf -sW → 导出 Java_..._stringFromJNI2 @0x1169（492B）+ isPrime @0x110d
  │      ⇒ 函数地址是奇数 = **Thumb**；源码目录泄露：AliCTF（flag 前缀 alictf{}）
  │ ⑥ 反汇编受阻：Kali objdump 报 "can't disassemble for architecture UNKNOWN"
  │      ⇒ 换 radare2 并显式指定 `-e asm.bits=16`（Thumb）
  │ ⑦ 读逻辑：函数用一堆 `__aeabi_d*`（dadd/ddiv/d2iz）**浮点混淆**逐字节算 buf[i]，
  │      按 isPrime(buf[0]) 分成两个分支；buf[13..16] 固定写 "3te7" 或 "=jo;"
  │ ⑧ 手算浮点常量太慢 ⇒ **上 Unicorn 模拟执行**（Kali 自带 unicorn 2.1.2）：
  │      映射 so + 处理 .rel.dyn(RELATIVE/GLOB_DAT) 与 .rel.plt、造栈、
  │      r2 = k = 1616384，LR = 哨兵 → 直接跑出 buf
  │ ⑨ 交叉验证：buf[11] 由 `k / 20992` 得出（0x12a0: movs r1,0xa4; lsls r1,7 ⇒ 164<<7）
  │      1616384 / 20992 = 77.0 = **'M'** —— 与模拟结果逐字节吻合 ✔
  ▼
alictf{Y0vAr3TimerMa3te7}
```

## 5. 已验证事实

1. **k 值**：`π(200000)=17984`；`k = 100×17984 − 182016 = 1616384`（Python 独立枚举累加得出，与 Java 逻辑逐步对应）。
2. **native 返回串**：Unicorn 完整执行 `stringFromJNI2(1616384)` 后，栈上 buf = `Y0vAr3TimerMa3te7`（17 字节 + NUL）。
3. **交叉验证**：反汇编中 `buf[11] = k / 20992`（`movs r1,0xa4` + `lsls r1,7`），手算 `1616384/20992 = 77` = `'M'`，与模拟输出的第 12 个字符完全一致。
4. **常量来源**：`buf[13..16]` 在素数分支写 `"3te7"`、非素数分支写 `"=jo;"`（反汇编直读）。
5. **语义自洽**：`Y0vAr3TimerMa3te7` 解读为 "You are Timer Ma3te7(=Master)"，与题目"倒计时/计时器"主题吻合。

## 6. 这道题的坑

1. 🔴 **模拟必须跑到"函数返回"，否则会得出错答案**：第一次模拟因假 JNIEnv 在 `NewStringUTF` 处
   `UC_ERR_READ_UNMAPPED` 中断，此时 `buf[12]` **尚未写入**（残留 0），我一度读出
   `Y0vAr3TimerM` —— **少了 5 个字符**。补上"假 JNIEnv（env→函数表→全填 `bx lr`）"让函数正常返回后，
   真实结果是 `Y0vAr3TimerMa3te7`。
   —— 判据：**只要模拟返回 err != None，就不能把当前内存当作最终输出**。
2. **so 不在解压目录里**：它嵌在 APK 内部的 `lib/armeabi/`，要单独 `zipfile.read()` 取出来，否则上传报"文件不存在"。
3. **Kali 的 objdump 不认这个 ARM so**（`architecture UNKNOWN`）→ 直接换 **radare2 并显式 `-e asm.bits=16`**，
   否则按 ARM 模式反汇编会出现 `unaligned` 之类的垃圾。
4. **Thumb 判定**：函数地址 `0x1169` 是**奇数**（LSB=1）= Thumb；Unicorn 里 `emu_start(addr|1)`、LR 也要 `|1`。
5. **GOT 要自己重定位**：静态读取时 GOT 全是 0，必须按 `.rel.dyn`（`R_ARM_RELATIVE` → `base+addend`，
   `R_ARM_GLOB_DAT` → 自备假地址）与 `.rel.plt` 填好，否则第一次 `ldr` 就跑飞。

## 8. 复现要点（方法）

**① Java 侧 k 值**
```python
def is2(n):
    if n <= 3: return n > 1
    if n % 2 == 0 or n % 3 == 0: return False
    i = 5
    while i*i <= n:
        if n % i == 0 or n % (i+2) == 0: return False
        i += 6
    return True
P = sum(is2(n) for n in range(1, 200001))     # 17984
k = 100*P - (200000 - P)                      # 1616384
```

**② Unicorn 模拟 native（关键骨架）**
```python
mu = Uc(UC_ARCH_ARM, UC_MODE_ARM | UC_MODE_THUMB)
mu.mem_map(BASE, size); mu.mem_write(BASE, open('liblhm.so','rb').read())
# .rel.dyn @0xfb8(9条)：R_ARM_RELATIVE(0x17) → base+原值；R_ARM_GLOB_DAT(0x15) → 自备假地址
# .rel.plt @0x1000(9条)：R_ARM_JUMP_SLOT(0x16) → 假函数
mu.mem_write(BXLR, bytes.fromhex('1eff2fe1'))            # ARM: bx lr
mu.mem_write(FUNCTAB, struct.pack('<I', BXLR) * 0x1000)  # 假 JNI 函数表：每格 bx lr
mu.mem_write(ENV_MEM, struct.pack('<I', FUNCTAB))        # 假 JNIEnv
mu.reg_write(UC_ARM_REG_R0, ENV_MEM)     # JNIEnv*
mu.reg_write(UC_ARM_REG_R1, ENV_MEM)     # jobject
mu.reg_write(UC_ARM_REG_R2, k)           # jint k
mu.reg_write(UC_ARM_REG_LR, SENTINEL | 1)
mu.emu_start((BASE + 0x1168) | 1, SENTINEL)              # Thumb 入口（LSB=1）
buf = mu.mem_read(SP0 - 0x30, 24)                        # buf = 入口SP - 0x30
```

## 9. 复盘：可复用的判断

| 触发信号 | 含义 | 动作 |
|---|---|---|
| APK 里带 `lib/**/*.so` | 校验在 native | 先 jadx 看 Java 侧"喂什么参数"，再专攻 so |
| 导出符号是 `Java_<包>_<类>_<方法>` | JNI 入口 | `readelf -sW` 拿地址；**地址为奇数即 Thumb** |
| so 导入一堆 `__aeabi_dadd/ddiv/d2iz` | **浮点混淆**（用 double 掩盖整数运算） | 别手算常量，直接上 Unicorn |
| `objdump` 报 architecture UNKNOWN | 该 binutils 不带该后端 | 换 `r2 -e asm.arch=arm -e asm.bits=16` 或 Ghidra |
| 想快速拿 native 函数输出 | — | **Unicorn 模拟**：映射 so + 手填 .rel.dyn/.rel.plt + 造栈 + 假 JNIEnv |
| 模拟结果里出现"可疑的 0 字节" | 很可能还没跑到写入点 | **必须确认 err=None（跑到函数返回）**，再取内存 |

## 11. 收尾三问

1. **触发信号**：APK + `.so` ⇒ **Java 只看"协议"，算法去 native**；so 里见到 `__aeabi_d*` 密集出现 ⇒ 浮点混淆，直接上模拟器。
2. **可迁移性**：**"Unicorn 跑 so 里的纯函数"** 是 ARM 逆向的通用加速器——只要函数是确定性的（输入→输出），
   映射 + 重定位 + 假 JNI/假 libc + 哨兵返回，就能在几秒内拿到结果，绕过所有浮点/混淆。
3. **边界 / 失败分支**：
   - 函数若调用外部 libc（memcpy/malloc）需一并提供假实现；
   - 若中途 `UcError` ⇒ **当前内存不是最终结果**，必须补齐桩函数让它返回；
   - 若存在反调试/环境校验（读 `/proc`、检测 frida）⇒ 需一并 hook 绕过；
   - 若 so 加壳（本题没有）⇒ 先脱壳再模拟。
