## 0. 一句话

`morluto/rea` 把「逆向一个**已编译产物**」这件事包成 **MCP server + CLI + agent skill**：
智能体（或你自己在终端里）可以调用 Ghidra / IDA / Hopper / JADX / Binwalk 等引擎去查目标，
**每条结论都附带 Evidence（证据 ID）、限制与未知项**。

它明确的分工是：*判断依赖"已发布的二进制或包、反编译结果、运行时证据"时用它；
对一份完整源码仓库做普通架构分析，不要用它。*

## 2. 为什么它对本项目有用

只列和 CTF / 逆向直接相关的行（完整表见 `README_zh.md` 的「可以分析什么」）：

| 目标 | REA 返回什么 | 需要什么 |
|---|---|---|
| **`.NET` 程序集** | 元数据、**CIL 指令**、声明的原生依赖、构建对比 | ⭐ **不需要任何引擎**，纯静态 |
| **原生二进制** | 伪代码、汇编、字符串、符号、调用与交叉引用 | Ghidra / IDA / Hopper 之一 |
| **离线 ELF 布局** | 节、段、原始符号/重定位、静态防护机制候选项 | 调用方提供 pwntools（Linux x64） |
| **已记录的 Linux 崩溃** | 每个线程的寄存器/信号、原始 note、映射候选项 | pwntools，(可选) GDB/pwndbg |
| **EVM 字节码** | 分派选择器、字节偏移、推断参数、状态可变性 | 就是字节/十六进制本身 |
| **固件** | 区域、提取结果 | Linux 上的 Binwalk / Unblob |
| **Android APK** | 清单声明、类、反编译方法、引用 | Linux/macOS 上的 headless JADX + 完整 JDK |
| **JS / Electron** | 模块、导入、source map、路由、IPC、原生扩展关系 | Node + npm |
| **网站** | 页面结构、脚本、网络观察、截图 | Chrome 系浏览器 |
| **已存的网络抓包** | 请求/响应/载荷/来源位置 | HAR（原生 mitmproxy 抓包需 Linux） |
| **归档/包** | ZIP/APK/IPA/MSIX/AppX/DMG 成员清单、plist | 无 |

**最值钱的是前两条：**

1. **`.NET` 那条 = 我们 `dn.py` + `il.py` 的第三方对照。**
   呼应 `04-踩坑` **G1**「自研解析器必须用第三方实现交叉验证」——
   我们已经用 `dnfile` 做了元数据层的交叉验证，但 **IL 指令层一直没人对**（见 `02-工具箱` §十二 的"残留"）。
   REA 的 `inspect_managed_artifact` 正好能补上这一层。
2. **原生二进制那条 = 把 `03-逆向SOP` 里"遇到大二进制就上带 GUI 的引擎"这一步自动化。**

> ⚠️ 它**不上传**目标文件，分析在本机跑。（但结论会喂给模型，模型侧数据政策另说。）

## 6. 本机是怎么拉下来的（`github.com` DNS 被卡）

**踩坑全文见 `04-踩坑与教训.md` → I 类。** 这里只放结论：

- 本机解析 `github.com` **超时**（所有公共 DNS 也不通），但 `codeload.github.com`、
  `api.github.com` **能解析**。`hosts` 无写权限，改不了。
- ✅ 可用镜像：**`gh-proxy.com`** —— 它**完整代理了 git smart-http 协议**
  （返回 `application/x-git-upload-pack-advertisement`），所以能做**真正的 `git clone`**，
  不是只能下 tarball。
- 已经在 `D:\rea` 里写了一条**局部**重写，以后 `git pull` / `git fetch` / 拉子模块都自动走镜像：

  ```bash
  git config url."https://gh-proxy.com/https://github.com/".insteadOf "https://github.com/"
  ```

  `git remote -v` 里 `origin` 因此显示成镜像地址，但 `.git/config` 里存的仍是官方的
  `https://github.com/morluto/rea.git`（换台机器/网络恢复后不动它也照样能用）。

## 10. 🔴 2026-10-11 实测校正（老板问"REA 你没用吗"之后补）

### 10.0 结论先说
**REA 一次都没用过。贡献 = 0。** 而"用不了"的借口是错的。

### 10.1 最大的错误：把"缺引擎"读成了"用不了"
`doctor` 报 `healthy=false` + 缺 Hopper/Ghidra/IDA 三个引擎 —— 我据此记为"体检通、缺引擎"，
**心里当成"REA 用不了"**。实测 `capabilities --json`：

| 项 | 值 |
|---|---|
| 总 operation | 18 |
| **available** | **8** |
| unavailable | 10 |
| **unavailable 的原因** | **全部是 `unsupported_host`（macOS 专属），一个都不是缺引擎** |

→ **缺引擎只砍掉 native（Ghidra/IDA/Hopper）那一条路。**
`inspect_managed_artifact` / `inspect_managed_members` / `inspect_managed_native_boundaries` /
`extract_artifact` / `inspect_artifact` / `inspect_keyed_archive` —— **全部 available，开箱可用。**

### 10.2 第二个错误：MCP 注册是**伪阻塞**
§4 写着"接进 WorkBuddy（手动注册 MCP）—— ⏳ 尚未执行"，把它当成前置条件。
实际 **`rea@6.4.0` 有完整的 CLI 命令面**（`analyze` / `inspect` / `function` / `decompile` /
`inspect-managed-members` / `extract-firmware` / `compare-managed-members` … 共 150+ 条），
**Bash 直接调即可，根本不需要 MCP 注册。**（本机 `~/.workbuddy/mcp.json` 至今不存在。）

### 10.3 实测证据（本机，真实跑过）

### 11.2 接线方式（老板定调：**都不要脱离系统**）
- REA 走 `ctf_rea.py` 适配器，已注册进 CTF-OS：`rea_status` / `rea_ops` / `rea_run`。

- 调用前先 `rea_ops` 读签名；`function` 的真实签名藏在**报错文本**里：
  `rea function <path> [address]` —— 直接猜参数会白跑一轮。

### 11.3 实测：与 x64dbg **同一样本**互证（probe32.exe）
| 侧 | 拿到的 | 值 |
|---|---|---|
| REA（静态） | 格式/架构 | `pe` / `x86`，sha256 `ffb03f11…` |
| REA（静态） | 段 | 6 段：`0x400000/0x401000/0x402000/0x403000/0x404000/0x405000` |
| REA（静态） | 入口函数 | `start` @ **`0x40100d`** |
| REA（静态） | `probe_add` 伪码 | `_DAT_00402000 = param_1 + 0x11;`（= 源码 `add eax,17`） |
| x64dbg（动态） | 主模块基址 | **`0xE00000`**（ASLR，≠ PE 头 `0x400000`） |
| x64dbg（动态） | 入口 | `entry_va = 0xE0100D` = `0xE00000 + 0x100D` |

→ **两侧地址换算关系：`运行地址 = ASLR基址 + RVA`，`RVA = 文件VA − 0x400000`。**
REA 给"文件里的地址"，x64dbg 给"运行时的地址"，**互补且可互证**。
x64dbg 侧单步读到的 `83 C0 11`（`add eax,0x11`）与 REA 伪码 `+ 0x11` 是同一件事。

| 场景 | 用谁 |
|---|---|

- REA 只读子命令可直接跑；`MUTATING` 里的要 `confirm=true`。
- 服务进程**必须由计划任务托管**（`CTF-OS-常驻`）—— 我起的进程会被回收，端口直接消失。
