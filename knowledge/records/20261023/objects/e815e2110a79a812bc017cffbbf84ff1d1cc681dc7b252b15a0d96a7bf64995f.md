## 一、环境接入（这次先踩平的坑）

### 1. 必须用对 Python 解释器

`[CTF_ROOT]\tools\ctf_os.py` 是统一入口，但**不能用 PATH 里的 `python`**：

- Doubao / PowerShell 默认 `python` 指向 sandbox runtime 的 3.13.13，缺 `requests`，会少注册 6 个 pwn.college 工具（42 → 36），Muteki 项报 `No module named 'requests'`。
- 正确解释器是 `启动CTF系统.bat` 里写死的 venv：
  ```
  [USER_HOME]\.workbuddy\binaries\python\envs\default\Scripts\python.exe
  ```
  这个有 `requests 2.34.2`，doctor 跑出来 `doctor_passed=true`、`all_items_available=true`、`registered_tools=42`。

所有调用固定走：
```powershell
$PY="[USER_HOME]\.workbuddy\binaries\python\envs\default\Scripts\python.exe"
& $PY [CTF_ROOT]\tools\ctf_os.py --once <tool> --args k=v ...
```

### 2. pwn.college 工作流（已验证）

```
pc_find   --args dojo=reversing-hell limit=99999     # 不传 dojo 则列全站
pc_pull   --args dojo=.. module=.. challenge=..        # 启容器 + 下载 + scp 到 Kali
pc_run    --args cmd=/challenge/main 'stdin=...' confirm=true
pc_submit --args dojo=.. module=.. challenge=.. 'flag=pwn.college{...}' confirm=true
```

`pc_pull` 自动把 `main` 下到 `题目库\pwn.college\<dojo>\<module>\<challenge>\`，并 scp 到 Kali（按文件 SHA256 隔离目录）。本机分析直接 `local_file=<本机路径>` 走桥，不用手动 scp。

### 3. PowerShell 传参坑

- `stdin` 值含反引号 `` ` ``、`@`、空格时，整个 `key=value` 用**单引号**包起来：
  `--args 'stdin=1mkOpD4`gFa4MBNUnrp2'`
  （双引号里反引号是转义符，会吃掉字符。）
- `kali_run` 的 `cmd` 不能含逗号（会被拆成 argv 数组导致 127）；`timeout` 上限 600 秒。

## 二、level02 —— 单字节 +3 变换

### 已验证

- ELF 64-bit x86-64 stripped，14408 B，动态链接。
- main (`0x4010b0`)：`scanf("%s",buf)` → 遍历 buf 每字节 `+= 3` → 三组比较：
  - `buf[0..8]  XOR 0x63374773526e7034 == 0`
  - `buf[8..16] XOR 0x585145503764496a == 0`
  - `buf[16..20] == 0x35737571`（小端 DWORD）
  - `buf[20] == 0`（正好 20 字符）
- 通过则 `fopen("/flag")` 打印。
- 逆变换：`C = T - 3`（每字节）。
- 算出 key：`1mkOpD4`gFa4MBNUnrp2`（20 字节，含反引号）。
- 容器内跑回 `Good job!`，flag `pwn.college{QCI_...}`，submit `already_solved`。

### 认知差

- 变换是**原地逐字节**，第一个字符也被 +3，不是从第二个开始。
- 小端 `movabs rax, 0x63374773526e7034` 在内存里按低字节在前存：`34 70 6e 52 73 47 37 63`，直接 `struct.pack('<Q', ...)` 再每个字节 -3 即可，别手排字节序。

## 三、level03 —— (C+3) ^ 2 变换

### 已验证

- 同模板 14408 B，但循环里多一条 `xor eax, 0x2`（`0x401107`）：
  ```
  add eax, 3
  xor eax, 2      ; level02 没有这步
  mov [rdx-1], al
  ```
- 变换公式：`T = (C + 3) ^ 2`，逆变换 `C = (T ^ 2) - 3`。
- 三组常量：
  - `rax = 0x456a594134685a4e`
  - `rdx = 0x544f494f79686534`
  - `DWORD = 0x79575378`
- Python 还原：`IUg3@XeD3dgxJHJSwNRx`（含 `@`），roundtrip 通过。
- submit 返回 `{"success": true, "status": "solved"}`。

### 认知差

- 每加一层变换，看循环体里有几条算术指令就行：level02 只有 `add 3`，level03 多了 `xor 2`。别被 14KB 的整体大小骗了——都是同一份 C 模板改常量和循环体。

## 四、level04 —— 4 整数方程 + 连字符格式

### 已验证

- 14424 B（比 level03 多 16 B），题型变了：不再是字符串变换。
- main：`scanf` 读一行 → `sscanf` 解析 4 个数 `a b c d` → check 函数 (`0x401310`) 验 4 个约束。
- 四个约束（寄存器：rbp=a, rbx=b, r12=c, eax=d）：
  1. `a*b + c - d = 0x340fe872`
  2. `b - a = 0x5ee9`
  3. `d - 5*c = 0xfffa3a38`（有符号 = **-378312**）
  4. `(d + b) mod 100000 = 0x40d3`（=16595，C 有符号取模）
- 还有前置：`a,b,c,d` 全不能为 0。
- Python 在 ±50000 范围搜索，唯一解：`a=19805, b=44102, c=90161, d=72493`。

### 关键踩坑：输入格式

第一次喂 `"19805 44102 90161 72493"`（空格分隔）→ `Wrong key!`。
`strings` 一看，sscanf 格式串是 **`%5s-%5s-%5s-%5s`**——连字符分隔，每段正好 5 个字符。

正确输入：`19805-44102-90161-72493` → `Good job!`，submit `solved`。

### 认知差

- **别猜输入格式**。看到 `sscanf` 一定要去 strings 里把格式串挖出来。`%5s` 限定长度，解出来的数正好 5 位是设计好的。
- `0xfffa3a38` 是有符号 32 位，Python 里要 `struct.unpack('<i', struct.pack('<I', 0xfffa3a38))[0]` 转成 -378312，别当无符号算。
- 第 4 个约束那段 `imul rdx, rdx, 0x14f8b589; sar rdx, 0x2d` 是编译器优化的有符号除以 100000（魔数除法），最后 `% 100000`。

## 六、可迁移套路

1. **babyrev 模板识别**：14KB 左右 stripped ELF，main 里 `scanf → 变换循环 → movabs 常量组 → fopen("/flag")`。看到这个结构，直接提取循环体算术 + 三组常量，Python 逆变换。
2. **逆变换模板**：
   ```python
   import struct
   T = struct.pack('<Q', c0) + struct.pack('<Q', c1) + struct.pack('<I', c2)
   C = bytes(逆变换(b) for b in T)
   ```
3. **数学题模板**：看到 `sscanf` + `strtol`，先 strings 拿格式串，再列方程，Python 搜小范围（通常唯一解）。
4. **报告铁律**：三栏（已验证/未验证/未完成），flag 是容器跑出来的不是手猜的。
