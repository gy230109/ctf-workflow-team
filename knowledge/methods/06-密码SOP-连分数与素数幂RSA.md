# 密码 SOP · 连分数与素数幂 RSA

来源：2026-10-10 [Factor 实战](../cases/Factor-20261010/README.md)。以下是从原始参数和实际解密验证提炼的检查顺序。

## 1. 分诊：先写关系，不先选大型工具

收到 Python 生成代码及打印整数，先只读解析。列出 `N` 的因子幂次、`φ(N)`、逆元关系、每个小参数的实际位数、以及各层传递的量。不要重新执行随机生成器；源码变量名笔误按公开输出核对，避免生成另一道题。

重点触发条件：`N=p^r*q`、两个素数异常接近、`e=inverse(d,φ)` 且 d 小、或 `e=inverse(a,φ)*b`。先检查 `gcd(e,N)`：非 1 时可能已经直接泄露因子，不能无条件取逆。

对**不同素数** p、q：

```text
N = p^r*q
φ(N) = p^(r−1)*(p−1)*(q−1)
λ(N) = lcm(p^(r−1)*(p−1), q−1)
```

若候选 p=q，公式需要另算；候选因子的素性前提也要注明。

## 2. 相近素数：模数比近似小因子比

Factor 第一层：`N1=p1²*q1`、`N2=p2²*q2`，p1、p2 极近，尝试 `N1/N2 ≈ q1/q2`。

1. 整数欧几里得算法生成 `N1/N2` 的连分数收敛分数 `u/v`。
2. 检查 `u>1,v>1,N1%u==0,N2%v==0`。
3. `isqrt(N1/u)` 和 `isqrt(N2/v)` 的平方必须精确等于商。用浮点根判断几千位整数会出错。
4. 验证附件给出的接近界，并验证实际 Legendre 条件：

```text
gcd(q1,q2)=1
2*abs(N1*q2−N2*q1)*q2 < N2
```

该条件等价于 `|N1/N2−q1/q2| < 1/(2*q2²)`，足以保证约分后的目标在收敛分数中。本题命中从 0 开始的索引 310。

**失败时**：接近程度未必足够；目标可能约分；或源码映射与假设不同。先查这些，再选择半收敛分数、其他约束或格方法。不要将“没有命中”当作无解。

## 3. 素数幂：先逆，再看有效分母

已知 `e*d ≡ 1 mod φ(N)`，d 小，且 `gcd(e,N)=1`。因为 N、φ 都含 `p^(r−1)`，对 `s=inverse(e,N)` 有：

```text
s ≡ d mod p^(r−1)
s = d + t*p^(r−1)
s/N = t/(p*q) + d/N
```

若 `gcd(t,p*q)=1` 且 `2*d*(p*q)² < N`，则 `t/(pq)` 是 `s/N` 的收敛分数。计算前通常不知道 t,p,q，可以先搜索候选；获得因子后必须补验这两个条件。

候选分母 v 的检查：

```text
N % v == 0
P = N // v
p = 整数 (r−1) 次根(P)
p^(r−1) == P
N % p^r == 0
q = N // p^r
p^r*q == N，p>1，q>1，p!=q
```

Factor 的 r=7，v=pq，`N/v=p⁶`；第二层索引 558。这里“小”的比较对象是 **pq 的平方与 N 的比**，不能直接按普通 Wiener 攻击的 N 四次根阈值判断。

**失败时**：若 `gcd(t,pq)>1`，分母是约分后的 `(pq)/g`，本工具的“商为精确 (r−1) 次幂”路线可能不命中。应结合已知因子、幂次、半收敛等继续分析。若误差界不成立，也不能保证只搜收敛分数足够。

## 4. 跨层中间量：解一个，再用一个

如果 `e_final = inverse(a,φ_final)*b`，且上层密文解出了 b：

1. 检查 b 非零、`e_final % b == 0`。
2. 用 `e_base=e_final/b` 重复第三节；Factor 第三层索引 598。
3. 因子恢复后，检查**完整** `gcd(e_final,φ_final)`。等于 1 才按逆指数解密；不等于 1 切换模根恢复并用题面约束筛选。

`e_final` 可以大于 N，也可能没有先模 φ；不要为了“标准 RSA”外观擅自截断原始公开值。

## 5. 最后验证：不仅看 flag 外形

- 精确核对全部模数因子乘积，且参数来自原始附件。
- 将每层明文用对应原始指数重新加密，严格等于原密文。
- 核对逆元恒等式、近似界、约分条件和实际位数。
- 另用不导入求解器的校验器复算；Factor 校验器使用 `λ(N)`。
- 对重复素数因子的模数，逆指数路线及唯一性在**单位群**上说明。先查 `gcd(c,N)=1`，不能直接宣称幂映射对所有模 N 整数都是置换。
- 输出 UTF-8 可打印明文、来源哈希与 JSON 证据。记录算法时间、加载时间、传输时间、墙钟时间各自口径。

模板中的“枚举多个 SMT 模型”针对约束求解题；本题用单位群上的可逆性说明唯一性，不编造 SMT 枚举。

## 6. 最小可运行工具与协作

`tools/solve_factor.py`：Factor 专用完整链，标准库、整数连分数及开根；失败会指出逆元、精确幂或约分等分支。

`tools/verify_factor.py`：独立解析原始 ZIP，重算因子、φ/λ、四层重新加密和近似界；不信任求解器布尔结论。

本地模型先给结构假设和可检验等式；Kali 执行确定性脚本；主模型处理推导卡点。为本地模型补此 SOP 的检索入口，比不断追问“继续分析”更可控。是否已提高其独立解题能力，需要另做同输入、同预算、同工具的测试。

## 7. 多项式秘密共享（Shamir）+ Lagrange 求 x=0（2026-10-11 新增，题：HTV2020-adobesecretreader）

- **判据**：源码里出现 `poly[0] = bytes_to_long(flag)`、`K = len(poly)`，
  以及 `y = Σ c_i·x^i mod prime` 的求值 + 生成 K 个不重复 `x` 的共享 `(x, y)`；
  prime 位数 = `8*len(flag)`（保证 `secret < prime`）。看到这一组就是 **Shamir 秘密共享**，flag 即常数项 `poly[0]`。
- **动作**：拿到 ≥ K 组 `(x, y)` 后，直接对 **x=0** 做 Lagrange 插值：

  ```text
  poly[0] = Σ_i y_i · Π_{j≠i} (0 - x_j)/(x_i - x_j)   (mod prime)
  ```
  再 `long_to_bytes(poly[0])` 即 flag。
- **载体陷阱（本题真坑）**：共享数据被塞进 **41 个串接的 PDF**，每份用**独立置换过的子集字体**渲染，
  `ToUnicode` 是**恒等映射** → 直接抽 PDF 文本全是乱码。
  正确做法：逐份抽 `FontFile2`，用**随包原字体**（`DejaVuSansMono.ttf`）做**字形轮廓逐字节比对**
  重建字符映射（本题 95/95 字形全部命中），再还原文本。
- **分诊提示**：`message` 里 `%PDF` 计数 > 1 → 先按 `%PDF` 切分，别当单个 PDF。
- **失败分支**：只读 PDF 文本流（恒等 ToUnicode 下必得乱码）；或错误地先暴力试 prime 因子（本题无需）。

> 佐证：`generate.py` 第 34 / 40 行给出 `poly[0] == bytes_to_long(flag.encode())` 的断言；
> 结论 `<历史答案已移除>` 为本地复算所得。

## 8. n=p^k 且 gcd(e,φ)≠1：e 次根 + 单位根枚举（2026-10-13 新增，题：QWB2023 not_only_rsa）

- **判据**：`crypto_factor(n)` 返回**单一素因子、指数 k>1** → `n = p^k`（素数幂）。
  此时 `φ(n) = p^(k−1)·(p−1)`。再查 `g = gcd(e, φ(n))`：
  - `g == 1` → 正常求 `d = e^{-1} mod φ` 解密；
  - `g != 1`（最常见是 `e | (p−1)`）→ **幂映射在模 p^k 上非双射**，求逆会 `ValueError: base is not invertible`。**必须改求 e 次根**。
- **通用动作（e 次根）**：令 `s = (p−1)/e`（要求 `gcd(e,s)=1`）。
  1) 模 p 的一个根：`x0 = c^(e^{-1} mod s) mod p`，满足 `x0^e ≡ c (mod p)`（因单位群中 `c^s ≡ 1`）。
  2) 取 e 次单位根：`ζ = r^s mod p`（随机 r，挑 `ζ≠1`），`ζ^e ≡ 1`。
  3) **Hensel 提升**到模 `p^k`：`m0 = lift(x0, c)`、`z5 = lift(ζ, 1)`，逐层 `x ← x − f(x)·f'(x)^{-1} (mod p^layer)`。
  4) **全部根** = `m0 · z5^j (mod n)`，`j = 0..e−1`；按题面约束（已知前缀/定长/可打印）**筛选**。
- **两个易错点**：
  - 有 **e 个根**，不是一个——不要取第一个根就报答案；
  - `m0` 的**落点随随机 ζ 变化**，命中索引每次都可能不同（本题实测 74096 / 161344 / 513086）→ **必须遍历全部根**。
- **验证**：把找回的根 `m` 重新加密，`math_modpow(m, e, n)` 必须**逐位等于** `c`；别只看 flag 外形。
- **失败分支**：`gcd(e,s) ≠ 1` 时不能直接取 `e^{-1} mod s`；需退回逐个 Hensel 提升每个候选根，或换 `s` 的其它分解。

> 佐证：QWB2023 `not_only_rsa`，`n=p^5`、`e=641747`、`(p−1) % e == 0`；
> 结论 `<历史答案已移除>` 为本地复算所得，且 `math_modpow(root,e,n)` 与附件 `c` 逐位一致。
> 战例：`战例库/QWB2023-Crypto-not_only_rsa/README.md`。

## 9. 复数 RSA（Gaussian 整数）+ 共享低位 + 二元格（2026-10-13 新增，题：QWB2023 babyrsa）

- **判据 A（复数 RSA）**：源码里 `m = Complex(bytes_to_long(前段), bytes_to_long(后段))`、
  `complex_mult/complex_pow(re,im 模 n)`、且 `e = inverse(d, (p*p−1)*(q*q−1))`
  → 明文在 **Gaussian 整数环 mod n** 上，**群阶 = `(p²−1)(q²−1)`**（不是 `(p−1)(q−1)`）。
  解密 = `complex_pow(c, d, n)`，flag = `long_to_bytes(m.re) + long_to_bytes(m.im)`（按做题时**前半/后半**拆法拼回）。
- **判据 B（共享低位）**：`p = (高位<<t) + k`、`q = (高位<<t) + k`（**同一个 k**）⇒ `p ≡ q (mod 2^t)`。
  先验：`p % 2^t == q % 2^t`；`n mod 2^t == k² mod 2^t`。
- **判据 C（小 d）**：`d = randrange(n^0.675, n^0.70)` → `d ≈ n^{0.675~0.70}`。
- **通用动作（共享低位 + 小 d 的二元格）**：
  1) `u0 = √n (mod 2^t)`（2-adic 开方，`p≡q` 时唯一根）；
  2) `v0 = (2·u0 + (n − u0²)·u0^{-1}) mod 2^{2t}` ≈ `(p+q)` 的低位；
  3) 由 `v0, n, e` 算 `a1,a2,a3`，构造小根方程 `F(x,y)= x·y² + a1·x·y + a2·x + a3`；
  4) 取界 `X ≈ 2·n^{α+δ−2}`、`Y ≈ 3·n^{0.5−2β}`（`α=e位/n位`、`β=t/n位`、`δ=0.70`），
     二元格 `(m,t)`（常用 `m=4,t=4`）→ **LLL** → 两向量 `resultant` 消元 → 解 `(x,y)`；
  5) `p+q = 2^{2t}·y + v0`，`p−q = √((p+q)²−4n)` → `p,q`。
  依据：论文 `A new attack on some RSA variants`（含同参数例子）。
- **性能坑**：与 §8 同款——构造/提升用**整数运算**，别用 sage 符号多项式（本题 LLL 本身约 50 s）。
- **附件无输出时**：动态附件只给 `task.py` 时，真实 `n/e/c` 从公开题解取并**标注来源**，本机只做算法复现；`p*q==n` + 重加密 == `c` 双向验证。

> 佐证：QWB2023 `babyrsa`。真机 Kali+sage 从 `(n,e)` 格分解出 `p,q`（与公开题解**逐位一致**，`p*q==n`）；
> 解密得 `<历史答案已移除>`，且 `complex_pow(m,e,n)==c`。
> 战例：`战例库/QWB2023-Crypto-babyrsa/README.md`。

## 10. .NET 内嵌密钥 + 逐块 AES（2026-10-13 记，题：QWB2025 PolyEncryption，状态：未复现）

- **判据**：附件 = `flag.enc`（**十六进制文本**）+ `app/*.dll`（.NET，伴 `runtimeconfig.json`）+ `run.sh`。
  `run.sh` 典型形如 `xxd -p -c 16 | while read line; do dotnet X.dll $line; done`
  → 输入按 **16 字节/行**逐块加密、结果拼接 ⇒ **每块独立，基本就是 AES-ECB**。
- **动作**：
  1) 先 `strings <dll>`：若见到 32 字节（64 hex）常量，先把它们当候选 AES-256 密钥试解；
  2) 不中就上 **.NET 反编译**（`ilspycmd` / dnSpy / ILSpy）看真正的密钥派生；
  3) 常见派生：`key = bytes([c ^ k for c in magic_numbers])`、`SHA256(常量)`、双常量拼接等。
- **工具坑**：`dotnet tool install ilspycmd` 需要 **dotnet SDK**（只装 runtime 会报 "download a .NET SDK"）；
  Kali 若无 NuGet 源也一样失败 → **提前把反编译器装好**，别等遇到题才装。
- **本次结果**：26 个 32 字节常量直接当键、XOR(0..255)/MD5/SHA1/SHA256 派生、双常量组合、ECB/CBC 全试 → **全部未命中**；
  只能确认「逐块 AES + 密钥在 dll 内派生（含混淆方法名 `<Shreck>/<Horror>/<Hack>/<Crack>`）」，**记为未复现**。
- **旁证手法**：同类题解见 `key=bytes([magic_num ^ 6 for magic_num in magic_numbers])` + `AES.MODE_ECB`——"魔数异或得键"是常见套路。

## 11. 密文与模数不互素：`gcd(N,c)` 泄露因子（2026-10-13 新增，题：QWB2025 check-little）

- **判据**：RSA 输出给了 `N, e, c`；`N` 很大（如 2048 bit）但**不要先分解**——先做一眼检查 `gcd(N, c)`。
  若题目把 `key`/明文构造成**与 N 共因子**（如 `c = key^e mod N` 且 `p | key`），则 `gcd(N,c)` 直接 = `p`。
- **动作**：`p = gcd(N,c)` → `q = N//p` → `φ = (p−1)(q−1)` → `d = e^{-1} mod φ` → `m = c^d mod N`。
  若 `gcd(e,φ) ≠ 1`，退到 §8 的 e 次根。
- **配套**：常见"RSA 只是给密钥的一环"——解出的 `key` 还要喂给 AES（注意 `long_to_bytes(key)[:16]` 这类**截断**、或 hash 派生）。
- **易误判**：`e = 3` 别条件反射做整数立方根——若 `key` 位数足够大（`key³ > N`），立方根不成立，真弱点是共因子。

> 佐证：QWB2025 `check-little`。CTF-OS `math_gcd(N,c)` 真机返回值 = 后续 `φ→d→key` 一致的因子；
> 解密得 `<历史答案已移除>`，且 AES-CBC 重加密 == 附件 ciphertext。
> 战例：`战例库/QWB2025-Crypto-check-little/README.md`。
