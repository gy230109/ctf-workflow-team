## 二、`dn.py` —— .NET PE / CLR 元数据解析器

**能力**：完全脱离 dnSpy/ILSpy 的纯 Python 解析。
覆盖 PE 节表、CLI Header、`#~` 表流、`#Strings` / `#US` / `#Blob` / `#GUID` 堆、
全部 64 张表的**行 schema**、coded index 宽度、压缩整数（compressed uint）。
这是后续所有 .NET 工具的地基。

```bash
python dn.py target.dll
# -> rows {0x0: 3, 0x1: 12, 0x2: 5, 0x4: 8, 0x6: 14, 0xa: 41, ...}
```

**核心 API**（在自己的脚本里 import 使用）：

```python
import os, importlib.util
BASE = os.path.dirname(os.path.abspath(__file__))
spec = importlib.util.spec_from_file_location('dn', os.path.join(BASE, 'dn.py'))
dn = importlib.util.module_from_spec(spec); spec.loader.exec_module(dn)

pe = dn.PE('target.dll')
pe.rows                  # {表号: 行数}
pe.secs                  # [(name, virtaddr, virtsize, rawoff, rawsize), ...]
pe.streams               # {'#~': (绝对偏移, 大小), '#Strings': ..., '#US': ...}
pe.str_at(i)             # #Strings 堆第 i 字节起的字符串
pe.us(i)                 # #US 堆（用户字符串）-> str（ldstr 用）
pe.blob(i)               # #Blob 堆
pe.r2o(rva)              # RVA -> 文件偏移（跨节自动算）
pe.blob_at(off)          # 读 ECMA-335 压缩整数 -> (值, 新偏移)
pe.tbl_off[t]            # 表 t 起始文件偏移
pe.rsize(t)              # 表 t 单行字节数（按堆大小自动切 2/4 字节）
pe.ti(t) / pe.ci(tables, bits)   # 表索引 / coded index 宽度
```

**已知坑**：

- `#Strings` 可能是**非 UTF-8**（本次 `qwb2022BlackJack` 就触发过）→ 内部已用 `utf-8 + 'replace'` 兜底；
  自己写解析时用 `decode('latin1')` 也不会崩。
- 表行 schema 必须**逐字**对齐 ECMA-335 II.22；错一个字段，后面全部错位。
  典型：`FieldRVA` = `[RVA(u4), Field(ti)]`（**RVA 在前**），写反了会得到 `None` 而非报错。
- 表头 `#~` 的 `HeapSizes` bit0/1/2 决定 `#Strings` / `#GUID` / `#Blob` 是 2 还是 4 字节索引，
  **不读这个字节会整体错位**。

## 三、`il.py` —— CIL 反汇编器

**能力**：把程序集里所有带 RVA 的方法反汇编成 `IL_xxxx: opcode operand` 文本，
并把 `call/callvirt/newobj` 的 token 解析成 `命名空间.类型::方法`，
`ldstr` 解析成实际字符串，`ldsfld/stfld` 解析成 `FIELD#rid`。

```bash
python il.py target.dll            # 只打印"含密码学痕迹"的方法
python il.py target.dll all        # 全量反汇编（本次战例用这个）
```

**已知坑（全是实战踩出来的）**：

| 坑 | 现象 | 解法 |
|---|---|---|
| `ldstr` 操作数是 **token** `0x70xxxxxx`，不是 `#US` 原始偏移 | `IndexError` / 解出乱码字符串 | 用 `v & 0xffffff` 取偏移 |
| 小方法头 vs 大方法头 | 读到垃圾指令、`op=0x72` 处错位 | 判 `(b0 & 3) == 2` 走 tiny header（`csz = b0 >> 2`），否则读 fat header |
| `calli` / `switch` 变长 | 反汇编器 desync | `switch` 操作数 = 4 + 4×n；`calli` 后跟签名 token |
| 方法体解析崩了却不知道 | 静默输出半截 | 已内置 `try/except`，输出 `ERR: ...` 与 `##### desync in ...` 标记 |
| 静态数组看不到内容 | 只有 `ldtoken tok0x4000003` | 用 `fld.py` 走 FieldRVA |

## 四、`fld.py` —— 静态数组 / FieldRVA 提取（本题的胜负手）

**能力**：把 `RuntimeHelpers.InitializeArray` 用的静态字节数组**真实内容**读出来。

```bash
python fld.py embedded.dll 3
# field 3 name= 'a' flags= 0x8056
# FieldRVA field#1 rva=0x... off=... data=3c64245633fb... ascii=b'<$V3\xfb...'
```

**为什么重要**：C# 里 `byte[] key = { ... }` 这种静态数组，
在 IL 里只表现为 `ldtoken tok0x4000003` + `InitializeArray`，**明文不在代码里**。
必须 `FieldDef(rid) → FieldRVA(rid) → RVA → 文件偏移` 才能拿到字节。

**已知坑**：

- `FieldRVA` 列顺序 `[RVA, Field]`（RVA 在前）。
- 同一个 RVA 上可能有多条 `FieldRVA` 行（共享数据），要按 `field` 列匹配 rid。
- 反复出现 `TypeError: unsupported operand ... NoneType + int`
  ⇒ 不是"没找到字段"，而是 **`r2o()` 返回了 None**（RVA 落进了未映射区），先查节表。

## 五、`orphan.py` —— 孤立方法体扫描

**能力**：正则扫 `.text` 里所有 fat method header（`1b 30`），
**不依赖 `MethodDef` 表**，把"被从元数据里摘掉、但代码还在"的方法体 dump 出来。
（本次就是靠它发现 `T1..ctor` 里藏着的判题逻辑。）

```bash
python orphan.py            # 注意：默认作用于 embedded.dll，改 P/BASE 即可复用
```

**已知坑**：误报多（任何恰好在数据里出现 `1b 30` 的地方都会命中），
所以脚本里加了三个过滤：`csz` 在 1..4000、不越界、代码里必须含 `0x72`（`ldstr`）。

## 六、`extract.py` —— 从解密流里抽取内嵌 PE

**能力**：在明文里找所有 `MZ`，校验 `PE\0\0` 与节表，按 `max(raw_off + raw_size)` 截出完整程序集。

## 七、`solve.py` —— 通用"XOR + AES-ECB"第一层解密

```bash
python solve.py <in> [out.bin] [xor_key=0x22] [aes_key_hex=Brainstorming!!!]
```

做三件事：字节级 XOR → `openssl enc -d -aes-128-ecb -nopad` → dump 字符串 + 检索 `flag{`/`MZ`/`BSJB`。

**已知坑**：
- **`Padding=Zeros` 必须配 `-nopad`**，否则 `openssl` 报 `bad encrypt`。
- 用 `-nopad` 时输入长度必须是 16 的整数倍；截断到 16 字节做自测会报错，**那是自测文件的问题，不是解密失败**。

## 九、`solve_z3b.py` —— LFSR + z3（本题核心求解器）

```bash
:: z3 装在托管解释器里（本机实测 z3 5.1.0）
"<本机路径>" solve_z3b.py
```

做四件事，值得作为"密码学约束求解"的**通用模板**：

1. 用 `BitVec` 建模状态机（`Concat(Extract(62,0,R), fb(R, taps))` 表达 `(R<<1)|fb`）；
2. `Solver(timeout=…)` 加约束（输出流 == 常量）；
3. **枚举多个模型**并打印关键字段（本题是 `key12`），用来判断解是否唯一；
4. 内置**纯 Python 复算**（不依赖 z3）并断言，作为独立验证。

**已知坑**：
- **耗时不可控**：本题 320 bit 约束 / 96 bit 未知，实测 **129 s**。预算模式下必须提前规划。
- `LShR(x, 64)` 在 64 位向量上是"越界移位"，z3 会返回 0；
  想表达"高位为 0"应显式写 `LShR(A, 32) == 0`，别写 64。
- 求出的解**可能有多组**。不要取第一组就跑，一定要**枚举 + 检查关键字段是否稳定**。
- 如果两个模型给出的关键字段不同，说明约束不足 → 回头补约束，**不能随便挑一个**。
