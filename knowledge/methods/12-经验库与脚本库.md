# 12 · 从「死知识」到「会长大」：经验库 + 脚本库

## 起因：老板一句话问到了虚处

> "我们这个工作流能起到啥作用呢，或者说能训练什么？
> 别人电脑上面没安装本地模型。"

两个问题其实指向同一件事：**这套东西的价值在哪，而且它能不能积累。**

## 先纠正一个误解：它不训练任何模型

本地模型在 `nodes.json` 里只是 6 个节点中的一个，标着 `optional`、`默认关`、
**不在主阶梯里**。主阶梯是 本地 Python → REA → Kali，全是确定性计算，跟模型无关。
所以"别人没装本地模型"对主流程**零影响**——这点设计上本来就成立。

真问题在下半句。**原来的 skill 是死知识**：`dispatch-table.md` 手写死的，
`triage.py` 的探测器硬编码的。我们写到哪它就会到哪，
新人装上和我们用三个月是同一份。**这不叫训练。**

## 换主语：训练的是派单规则库

不是让模型变强，是让 `triage` 的命中率变高。载体是纯文本 JSON，不需要 GPU。

```
练题套 ──写入──▶ 经验库 ──查表──▶ 比赛套
   ▲                                 │
   └──────────── 打完记一笔 ─────────┘
```

**练题套生产规则，比赛套消费规则。** 混着干两头落空：
练题时不记经验 → 库永远是空的；比赛时写文档 → 白白丢时间。

| | 练题套 | 比赛套 |
|---|---|---|
| 验收 | 服务端 `solved`（强信号） | 本地三重校验（弱信号） |
| **产出** | **不是 flag，是经验** | **才是 flag** |
| 写经验库 | **必须写** | **别写** |

## 经验库：miss 比 hit 值钱

```bash
python scripts/exp.py add --sig rsa.multi_modulus --level 0 \
       --node local_python --action pairwise_gcd --outcome hit \
       --cost 秒级 --note "66对gcd全中同一个512位素因子" --ev n_count=12

python scripts/exp.py lookup --sig rsa      # 下次先查
```

设计要点：

- **sig 点分层级**（`rsa.multi_modulus`、`hash.md5_preimage`）→ `--sig rsa` 能捞整个家族
- **miss 记录才是资产**。它标记"这条路已经烧过时间了"，
  `triage.py` 会把它顶到最前面警告别重复烧
- **只记特征不记答案**。flag、题目名一律不写——这是要分发出去的
- 种子在 `experience/seed.jsonl`（脱敏、随包），本机攒的写 `experience.jsonl`

## 脚本库：有现成的就别自己写

`solvers/` 5 个，纯标准库，统一契约（CLI 输入 / JSON 输出 / `--selftest`）：

| 脚本 | 干什么 | 自测 |
|---|---|---|
| `shared_prime.py` | 多模数两两 GCD → 分解 | 3 个 512 位模数 3 对全中 |
| `chain_rsa.py` | 链式 RSA 逆推，DFS + `m < n_{i-1}` 约束 | 4 轮链式，恰好 1 解 |
| `factor_ladder.py` | 试除 → 完全幂次 → Fermat → rho | 四条路各自独立验证 |
| `md5_crack.py` | 哈希三级降级，跑完说该不该派 Kali | md5 穷举命中 |
| `reversible_xform.py` | 已知明文前缀反推变换和密钥 | xor/add/xor0xff 三类 |

### 实战验证：`chain_rsa.py` 跑 EasyRsa

```
"solutions": 1, "unique": true, "nodes": 34,
"plaintext": ["GWHT{gixkJl7SJTcpLOL9zqwo}"]
```

与我之前手工解出的结果一致，且 `unique: true`、`candidates_per_level` 有据可查。
**这就是脚本库的意义：同样的坑不会再踩第二次。**

## 自测踩到的两个坑（值得记）

1. **自测自己踩自己的边界**：`factor_ladder` 用小因子 `1000003` 做自测，
   但默认试除上限就是 `1000000` → 永远找不到。改成 CTF 里更常见的 `65537`。
2. **前面的方法抢跑，后面的没测到**：rho 那个 case 原本被 Fermat 秒解了，
   等于 rho 一行没跑到。改成两个**相距很远**的素数（24 位 × 28 位）才逼出 rho。
   **自测必须保证被测的那条路真的被走了**，不能只看"结果是通的"。
