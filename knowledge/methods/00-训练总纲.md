# 00 · 训练总纲

## 一、我们的目标定义

不追求"某次刷出 flag"，追求 **可重复的解题能力**。三个可量化的子目标：

| 指标 | 当前 | 目标 |
|---|---|---|
| 首轮（8 次调用 / 120 s）解出率 | 0 / 1 | ≥ 50% |
| 单题平均工具调用数 | 7（触顶） | ≤ 5 |
| "解出但没验证"的比例 | 0 | 保持 0（硬红线） |

## 二、最核心的方法论：**先分诊，再深挖**

90% 的翻车都是"没分诊就开始爆破"。正确顺序：

```
① 认题型   →  ② 找明文字面量  →  ③ 定算法栈  →  ④ 定约束/密钥  →  ⑤ 计算  →  ⑥ 验证
   10%预算       15%                20%              25%           25%      5%
```

**严禁**在第 ① 步就写"穷举 200 组密钥"这种脚本 —— 那是把 60% 的预算扔进垃圾桶。
（QWB2022 战例就是这么翻的，见 `01-战例` §7。）

## 三、预算纪律（针对 8 次调用 / 120 秒这类硬限制）

### 3.1 调用配比建议

| 调用 | 用途 | 反面教材 |
|---|---|---|
| 1 | 文件清单 + 体积 + 头部 hex + 熵 | 不要在这一步做完整字符串 dump |
| 2 | 字符串字面量 + 符号表（一次拿到位） | 不要分 3 次逐步 grep |
| 3 | 结构判定（分组长度 / 压缩 / 封装格式 / 元数据表） | — |
| 4–5 | **自研最小解析器**（这是本地模型的加分项，见 §五） | 不要用轮子试错 |
| 6 | 关键算法定位（IL / 反汇编 / 常量提取） | — |
| 7 | 求解（z3 / 线性代数 / 解密） | — |
| 8 | **验证**（独立复算，必须留） | 绝不能把第 8 次花在"再试一个猜测"上 |

### 3.2 时间成本意识（本机实测）

| 操作 | 实测耗时 | 结论 |
|---|---|---|
| 一次 Bash 调用（含进程启动 + 沙箱） | 1–8 s | 正常 |
| `grep` 全量字符串 + 关键词过滤 | 3–7 s | 便宜，可以多用 |
| ~200 组"密钥 × 模式"爆破（openssl 循环） | **56 s** | **昂贵，要放到最后** |
| z3 求解 320 bit × 3 个 64bit LFSR | **129 s** | 单步就能吃满 120 s 预算，**必须提前规划** |

> **教训**：任何"单步可能 > 60 s"的操作，在预算模式下要么不用，要么换更省的做法
> （例：先用纯 Python 整数公式替 z3 试小范围；先用位运算推线性关系再用 z3 收尾）。

### 3.3 触顶时的动作

不要"再抢救一次"。正确动作是：
1. 停；
2. 把**已确证的事实**列成表（这些是后续复用的资产）；
3. 把**未证实的假设**单独标注为"未验证"，不得混入结论；
4. 出 `NOT_SOLVED` 报告，并写明"如果再给 N 次调用，我会先做 X"。

## 四、本地模型的四个刻意练习方向

### 4.1 自己造工具（最高价值）

CTF 里"顺手工具"经常不存在（本机就没有 ILSpy / dnSpy / pycryptodome / file / bc）。
**能当场写出一个最小可用解析器，是本地模型最该练的能力。**

模板：自己造解析器时，永远按这个骨架写 ——

```
读 → 定位表/段 → 校验尺寸自洽 → 逐行 dump → 用 2~3 个已知样本断言
```

例：`.NET PE / CLR 元数据解析器`（`tools/dn.py`，约 180 行）——
只要读懂 ECMA-335 的 II.24 章，就能把 `#~` 表流、`#Strings` / `#US` / `#Blob` / `#GUID` 全解出来，
之后任何 .NET 题都不再依赖图形工具。

### 4.2 把"字符串发现"升级为"结构发现"

`grep` 到 `RijndaelManaged` 只说明"用了 AES"，**不说明怎么用**。
必须继续拿到：`set_Mode` 的实参（2=ECB）、`set_Padding` 的实参（3=Zeros）、`Key` 的来源数组。
**枚举值含义是常识，必须张口就来：**

| 枚举 | 值 |
|---|---|
| `CipherMode` | CBC=1, **ECB=2**, OFB=3, CFB=4, CTS=5 |
| `PaddingMode` | None=1, PKCS7=2, **Zeros=3**, ANSIX923=4, ISO10126=5 |

### 4.3 学会"低成本排除"

在写爆破脚本之前，先做**零成本判据**：

- 密文长度 mod 分组长度；重复块统计 → 立刻区分 ECB / CBC / 流密码（见 `03-SOP` §2）
- 文件头 magic → 立刻定封装格式
- 元数据里的"奇怪长 hex 字符串"→ 先当成 `SHA256/HMAC` 结果反查，而不是当成密钥

### 4.4 强制自我验证（红线）

**任何结论在写进报告前，必须换一条路径独立复算一次。**

合格的验证方式（至少选一）：
- 用纯 Python 整数/位运算重跑一遍密码学/算法逻辑，断言输出与二进制常量逐字节相等；
- 枚举多个求解模型的解，检查我们真正需要的部分（如密钥低 96 位）是否**唯一**；
- 用 `re.finditer` 在原始二进制里**反查**常量，证明来源可追溯、不是拼凑的。

不合格的"验证"（都不算）：
- "解出来是乱码 → 大概密钥错了 → 我换个密钥"
- "结果看起来像 flag"（没有任何独立交叉检查）

## 五、评分标准（每次训练后自评）

| 维度 | 权重 | 说明 |
|---|---|---|
| 是否正确解出 | 30 | SOLVED / NOT_SOLVED |
| 验证是否充分 | 25 | 有没有独立复算；结论可追溯性 |
| 预算利用效率 | 20 | 调用数、耗时是否接近 §3.1 配比 |
| 工具自造能力 | 15 | 是否被迫自己写解析器；代码能否复用 |
| 复盘质量 | 10 | 是否产出了可复用的 SOP 条目 |

> 只拿到 flag 但验证不充分 → 该次训练**不及格**（因为会把坏习惯带进下一次）。

## 六、每次训练的固定动作

1. **开始前**：记录界面显示的模型名称与版本（拿不到版本号就写"未知"，**不推测**）。
2. **过程中**：留一份 `工具调用记录表`（编号 / 输入 / 输出要点 / 错误 / 耗时）。
3. **结束时**：
   - 写战例报告（用 `模板\解题报告模板.md`）；
   - 勾选 `03-逆向SOP` 里被验证过/被推翻的条目；
   - 把新坑追加到 `04-踩坑与教训.md`；
   - 把可复用脚本搬进 `tools\` 并登记。
