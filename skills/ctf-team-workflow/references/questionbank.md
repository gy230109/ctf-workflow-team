# 本机题库训练与团队轮换

题库目录记录、已下载附件、可运行环境和已验证题解是四个不同状态。先读取仓库 `docs/questionbank.md` 的本批交付状态和来源清单，再使用本机题库 CLI；不能把云端生成完成或 2,485 条目录记录当成本机已有 2,485 道可运行题。

## 从选题到 Kali

1. 在本机题库运行 stats/search，按 category、来源、难度、附件可用性和授权范围筛选。字段缺失要标未知，不根据题名编造难度或类型。
2. 明确一题后，下载其原始附件到本机独立目录，核对来源、字节数和 SHA256。在线实验可能必须在原平台启动自己的实例，没有附件也不能算下载失败。
3. 只把题面和原 handout 交给解题 Agent；题解、参考答案、历史 solver 和题库管理者的校验材料隔离。发现 README 内含答案时标记/隔离该段，不作为解题输入。
4. 以题源+赛事+题名生成唯一 case；同题多附件属于同 case，不把一个附件计成一道新题。
5. `wp_init`，走 CTF-OS 的 `local_file` 上传或桥 put。Kali 执行使用同题目录；工具真实输出与回收摘要进入 WP。
6. 根据题目要求建立本地 Docker/运行时或原平台实例。源码/附件下载通过不代表服务已经启动。没有实际靶场和运行证据不能登记为 solved。
7. 复核后保存本机训练记录与 WP；上传代码与通用方法需另有用户授权，默认不上传每个人的账号或个人答案。

## 第一轮的评价方法

仓库本批题源数量、目录记录、已下载题数/附件数和环境验收状态必须由实际 catalog/manifest/下载记录给出。若本批原文件尚未接入，明确当前状态，不造一个同名“已下载题库”替代。

轮换表是计划。六人训练可以轮换 Web/Pwn/Reverse/Crypto/Misc/Forensics，让每人保留一个独立 case 的完整证据，并由另一位同学复核；不要把六个人每次全塞进同一调试器或共享可变状态。

记录每题：来源与 ID、类别、环境、起止时间、AI/工具预算、附件 SHA、关键调用、候选/验证、阻塞原因、复核者和 WP 路径。模型比较采用相同题目/预算和盲测输入，不给候选参考答案。

## 去重与可用性

题名相同不一定同题，来源相同也可能附件版本不同。优先比较来源 ID、赛事与附件 SHA；缺稳定 ID 时保留可能重复标记，不强行归并。附件总数可能大于题数。课程练习、比赛题和在线实验分开统计，防止规模数字掩盖运行条件。

## 更新与数据边界

公共目录和下载方法可以随仓库更新；下载后的附件、平台登录态、训练成绩和 WP 仅在本机。公共目录不应内嵌私密答案或个人 solver。只使用官方/明确授权题源，保留出处和许可信息；遇到登录、访问限制或不允许镜像的内容按原平台使用，不绕过限制。
