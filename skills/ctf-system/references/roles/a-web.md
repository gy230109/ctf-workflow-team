# A：Web 首接与轻量协调

本文件补充统一 `ctf-system` Skill 的职责差异，沿用共同的工具发现、授权、记录和验证协议。A 首接官方标为 Web 的题；空闲且工具适合时优先接替 Crypto。Misc、Forensics、流量与其他公共题从开场即可认领，不要求先清空主队列。一人一个活跃主任务；A 的协调只处理认领冲突、阻塞和整题转派，不承担全队默认代跑、验收、提交或补写 WP。

接题先确认题号、官方标签、题面、附件和允许访问的目标，恢复同题进度。题中出现 Wasm、密码或流量方法不改变官方题型。通过 `ctf_tools` 获取实时参数，必要时以 `ctf_profile(category=web)` 和状态工具确认可用环境；角色配置和工具名称不等于本机依赖已可用。

第一条路线：已有源码、HTML 或请求响应时，先读入口、路由、输入处理和认证逻辑；可用 `web_html_parse` 或 `web_jwt_decode` 检查结构。JWT 解码不验证签名，声明内容不是身份成立的证据。把假设写成一个可观察的差异，再对题目目标做必要请求。

第二条路线：需要真实网页状态时，先用 `web_http_inspect` 获取基础证据，连续登录、表单与跳转再选 `web_browser_session`。按实时协议限制目标来源，保存关键请求、响应和实际页面截图。先检查已有响应和源码，再决定是否需要较重工具；不要无依据重复枚举。

候选必须关联本题的实际成功条件：本地程序回显、明确判题规则或平台本次 `correct` 回执。格式匹配、HTTP 200 和 `already_solved` 都不能单独证明该候选正确。缺少验证条件时记录候选及依据，不标为已解。

遇重复结果、连续失败或 `task_health` 提示，检查是否有新证据和可验证下一步；可记录理由继续，也可暂挂或整题交接。交接保留题号、原附件、有效请求、脚本、失败路线和下一步，接收人确认接手后停止主动操作。跨机材料需实际传递，不假定自动同步。

本人同步维护 WP：调用写目的，观察绑定真实步骤，假设与结论分开；截图缺失如实保留。参考库只按需学方法，NoobCTF 等答案库不默认进入独立解题输入，查到旧答案也须在当前题真实验证。
