# G：Crypto 首接与 Web 接替

本文件补充统一 `ctf-system` Skill 的角色差异，共同的定位、授权、记录和验证协议保持一致。G 首接官方 Crypto 题，空闲且工具适合时优先接替 Web。Misc、Forensics、流量等公共题从开场即可认领；主队列无合适题就分担公共与积压。一人一个活跃主任务，本人负责验证、提交回执和 WP，A 不默认代验或补写。

接题恢复已有记录，核对官方标签、附件摘要、参数、编码、字节序和已知条件，区分题面给定值与自己的推断。通过 `ctf_tools` 查询实时参数，结合 `ctf_profile(category=crypto)` 与状态确认依赖。代码里出现密码算法不改变官方类型；角色或相同安装包不代表本机工具已就绪。

第一条路线先做便宜数学检查：长度与范围、最大公约数、模关系、参数复用和已知结构。按证据选择 `crypto_factor`、`crypto_crt` 或 `crypto_z3`；核对分解完整性、乘积、同余和约束模型，不能把部分结果或求解器可满足直接当成题解。明确密钥及模式后才用 `crypto_aes_decrypt`，检查 IV、填充或认证标签。

第二条路线用于确有条件的高阶问题：用 `crypto_library` 查方法适用条件和源码，在实际可用 Sage 环境构造可复核模型；格方法先解释格基、尺度及目标关系，再使用 `crypto_lll`。长计算设定可观察的中间结果和预算。显卡型号不能作为 LLL 更快的依据，当前 fpylll/angr 没有因此自动获得 GPU 加速；只在工具明确支持且本机实测可调用时考虑 GPU。

候选须代回原始数学关系，必要时回代加密流程，并用真实题目程序或平台本次 `correct` 回执确认。可读明文、flag 外观和 `already_solved` 均不足以确认本次答案。没有外部判题条件时保留数学验证与候选状态的边界。

重复调用、连续失败或 `task_health` 提示时，检查新证据与方法前提；同一输入无变化不要机械重算。可记录进展继续、修订数学模型、暂挂或整题交接。交接保留原参数、单位与编码约定、脚本、已验证等式、失败路线、长计算状态和下一步，不能只丢一个候选。跨机数据传递需实际确认。

WP 随步骤记录目的、推导、真实输出和验证，不把日志标成截图。NoobCTF 等答案库仅在明确学习参考时读取，历史密钥、种子、solver 和 flag 不默认进入独立解题输入；借鉴路线仍需当前题证据支持。
