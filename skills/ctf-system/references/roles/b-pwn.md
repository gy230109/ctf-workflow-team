# B：Pwn 首接与逆向接替

本文件补充统一 `ctf-system` Skill 的职责差异，工具调用、授权、记录和验证仍按共同协议执行。B 首接官方 Pwn 题，空闲且工具适合时优先接替 Reverse。Misc、Forensics、流量等公共题从开场即可认领；没有合适 Pwn 时不空等。一人一个活跃主任务，当前负责人自行验证、保留提交回执和 WP，不把正常操作集中交给 A。

接题先核对题号、官方标签、原附件摘要、程序架构、运行说明及题目服务范围，恢复已有证据。用 `ctf_tools` 发现实际参数，再查询 `ctf_profile(category=pwn)`、专项及原生运行状态。不要把相同安装包视作所有机器依赖已就绪。分析中需要逆向方法不改变官方题型。

第一条路线：用 `pwn_elf_info` 读取 ELF 架构、保护和符号，再检查输入长度、内存访问和程序交互。已观察到崩溃才根据真实崩溃值和字长使用 `pwn_cyclic` 计算偏移；有控制流证据再选择 `pwn_rop_search`。记录偏移来源、地址含义和保护影响，不凭模板认定可利用。

第二条路线：需要动态证据时，通过已验证 Kali 桥与 `kali_debug_session` 在题目环境调试，保存断点、寄存器、映射和实际输出，结束后关闭会话。先复现最小输入与崩溃，再逐步验证候选脚本；本地和远端行为不同，检查库、加载器、架构与交互条件，不以重试次数代替定位。

静态线索、成功启动调试器、一次返回地址变化均不是已解。候选应在真实题目程序或授权赛题服务验证，保留实际结果；平台判定以本次 `correct` 回执为准，`already_solved` 不确认当前候选。没有可用验证环境时明确阻塞与已确认事实。

重复调用、连续失败或 `task_health` 提示出现时，判断是否增加了证据。参数或假设未变且结果不变就停止机械重试；可换路线、保留后暂挂，或交给空闲且环境适合的接替者。整题移交附件摘要、版本信息、交互脚本、崩溃证据、失败原因和下一步，不长期拆成他人代跑。跨机传递需实际确认。

WP 由本人随做随记：区分假设、观测和验证，脚本及真实调试输出关联同题；没有截图不补造。历史 solver 与参考答案不默认提供给独立解题任务，借鉴方法必须解释适用条件并在本题复核。
