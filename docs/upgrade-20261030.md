# 2026-10-30 双模块更新

本次更新将解题能力和 WP 书写分别明确，保留传统 CTF 与破甲全部既有工具接口，按题目证据选用工具、链路或角色协作。破甲可承担主力。

Git 安装：先检查本地改动，保存后执行 git pull --ff-only，再重连当前 MCP。ZIP 安装：在新目录解压，按现有升级流程保留本机 config、身份、SSH 和 wp；不要覆盖这些私人数据。

接题和续题会返回双模块规则。ctf_plan、ctf_checkpoint、ctf_result 和 ctf_board 分别登记题目要求、检查点、真实结果与本机进度。ctf_team_role 兼容接口继续保留。角色协作和环境检查通过实时 ctf_tools 发现；角色工作流需要本机实际可用的后端。

截图选择关键且合适的题面、线索、操作或调试画面，以及 flag 结果/验证回执。保存原图、来源、步骤和 SHA256，并在 Word 正文嵌入。wp_capture 可用 stage=process、result 或 process_and_result；结果图必须引用实际 source_step。同一张图同时说明过程和结果时不强制重复拍摄。日志渲染和回放不冒充截图。

规范正文包括 overview、analysis、solution、validation、reproduction，引用真实 source_steps。缺图或正文缺项时，ctf_finish 拒绝作为完整稿交付；确需缺项草稿可使用 allow_incomplete=true。截图失败保留错误，不为补拍重复执行有副作用的动作。

修复内容包括能力查询从真实注册表读取、REA 使用 rea_run、未知体检项保留 na、轻量版本健康探测和实际字符串中换行 flag 的识别。Windows 环境检查复用当前安装环境，其他平台需单独核验。

检查命令：python tools/test_ctf_quality_20261030.py；python -m unittest discover -s tests -p "test_ctf_wp*.py"。专项 23 项、WP 48 项在维护环境通过，4 项可选检查跳过；这不代表比赛解题率或所有依赖均已就绪。
