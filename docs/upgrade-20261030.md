# 2026-10-30 双模块更新

本次更新将解题能力和 WP 书写分别明确，保留传统 CTF 与破甲全部既有工具接口，按题目证据选用工具、链路或角色协作。破甲可承担主力。

Git 安装：先检查本地改动，保存后执行 git pull --ff-only，再重连当前 MCP。ZIP 安装：在新目录解压，按现有升级流程保留本机 config、身份、SSH 和 wp；不要覆盖这些私人数据。

接题和续题会返回双模块规则。ctf_plan、ctf_checkpoint、ctf_result 和 ctf_board 分别登记题目要求、检查点、真实结果与本机进度。ctf_team_role 兼容接口继续保留。角色协作和环境检查通过实时 ctf_tools 发现；角色工作流需要本机实际可用的后端。

截图选择关键且合适的题面、线索、操作或调试画面，以及 flag 结果/验证回执。保存原图、来源、步骤和 SHA256，并在 Word 正文嵌入。wp_capture 可用 stage=process、result 或 process_and_result；结果图必须引用实际 source_step。同一张图同时说明过程和结果时不强制重复拍摄。日志渲染和回放不冒充截图。

规范正文包括 overview、analysis、solution、validation、reproduction，引用真实 source_steps。缺图或正文缺项时，ctf_finish 拒绝作为完整稿交付；确需缺项草稿可使用 allow_incomplete=true。截图失败保留错误，不为补拍重复执行有副作用的动作。

修复内容包括能力查询从真实注册表读取、REA 使用 rea_run、未知体检项保留 na、轻量版本健康探测和实际字符串中换行 flag 的识别。Windows 环境检查复用当前安装环境，其他平台需单独核验。

检查命令：python tools/test_ctf_quality_20261030.py；python -m unittest discover -s tests -p "test_ctf_wp*.py"。专项 23 项、WP 48 项在维护环境通过，4 项可选检查跳过；这不代表比赛解题率或所有依赖均已就绪。

## 2026-10-30 真实截图纠错

统一黑底日志图、登录/锁屏、空桌面、回放渲染和事后复刻页面不能作为解题截图。浏览器对复刻页面拍到的真PNG也不证明原操作发生。规范WP不再允许include_log_renders=true。

拿到图后必须用图像查看工具打开原图，核对实际应用/页面、命令或输入、输出与source_step；再用wp_capture_review记录image_step、image_sha256、accepted/rejected、capture_origin、observed_content及reason。只有核验通过且可读的原图计入完整性并嵌入正文；重复SHA256只展示一次，原文件保留。核验记录只表示审阅者观察，不是自动图像真实性认证。旧案没有记录核验的图片默认待核验；禁止追补虚构历史。

SSH命令执行并不出现在Kali桌面。需要终端截图时，应在执行前使用真实可见终端，在运行时采集；已执行的后台命令保留原始输出和截图缺项，不事后打印日志、重跑命令或造页面凑图。解题能力与破甲融合策略不变。

需要命令行关键截图时，使用kali_terminal_record(argv=[...], capture_window=true, confirm=true, timeout=60)。该模式在有认证、禁用TCP的隔离X11显示器里启动真正的xterm，在其中执行一次原命令、录制同次PTY并采集原窗口，不依赖用户桌面登录，不读取旧日志做图；程序退出码与截图成功分别保留。缺依赖会在执行命令前报错；执行后采集失败明确禁止重跑。可选依赖为xterm、Xvfb、xauth、xdpyinfo、xdotool、ImageMagick import和asciinema，由ctf_runtime_status.live_terminal_capture现测；缺项按平台补齐。核验时若同一原图同时包含实际命令和结果，wp_capture_review可用stage=process_and_result，无须再导入副本。

## 2026-10-30 WP 短板改进（wpboost）

围绕WP链路易用性与容错：wp_section的source_steps报错直接列出全部可引用步骤号，并提示wp_operation.operation_id不是步骤号；wp_purpose/wp_expectation缺失时兜底继承operation_started里执行前记录的值。新增ctf_note(amend_purpose=true)事后补记行动目的，追加purpose_amendment事件并标记recorded_after_the_fact，不篡改原call事件，已有执行前目的则拒绝补记；体检把补记过的调用计为已覆盖并单列purposes_amended_after_the_fact。

wp_capture新增auto_review=true自动像素预检：仅做机械检查（尺寸/非空白/非锁屏纯色），生成observed_content草稿并落image_review事件，人工可事后改写或rejected，不冒充人工语义审阅。图片口径统一：须经wp_capture_review accepted才计入完整性与导出件，相关测试已按新口径改写（原test_ctf_wp_real_capture.py并入新流程覆盖）。

ctf_tools空字符串name/query现按"列出全部"处理并返回total，不再误报0个工具。wp_status每个缺项附带具体补法提示（补目的/补观察/补章节/补截图/导出草稿）。交付docx被占用（WinError 32）或被编辑过时自动改存带时间戳的新文件名，不阻塞导出、不删用户正打开的文档。wp_build未嵌图时的screenshots_complete口径与wp_status对齐：本题无已核验截图时不再重复压低完成度。

检查命令：python tools/test_ctf_quality_20261030.py（专项23项）；python -m unittest discover -s tests -p "test_ctf_wp*.py"。WP回归59项通过，4项可选检查跳过。
