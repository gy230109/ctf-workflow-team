# 四人题目分配方案

版本：2026-10-16 能力增强后修订版。适用：2026-10-17 周六 A、B、D、G 四人参赛。只规定现有系统和配置下怎样分题，不安排安装、训练或赛前具体任务。成员代号对应沿用队内记录。

分配前提：全员共享系统内容和经验，出题方标明题型。四个主要队列分开首接，其他类别共同认领。

本轮流量工具、停滞提示、参考检索和 WP 附件增强，不改变四个首接队列。调整的是公共题的认领机会、无进展时的复核与整题交接；不增加第五个工作位，也不设置多模型竞速岗位。

## 一 分配依据

分配按统一底座、官方题型、当前负载与实际可执行条件进行。A 的工具、SOP、案例和方法不作为独占资源，不据此推定 A 必须承担 Misc/Forensics。题型直接使用出题方标注，不另设人工分型岗位。

四台宿主内存均约 16GB，CPU 均能承担常规分析。G 的显卡型号较高只影响经过确认的 GPU 任务，不代表密码题必然更快。用户提供的口径为成员无明显专长差异、模型同类，因此姓名与题型的初始对应是覆盖安排，没有证据证明某个人名排列绝对最优。确定一次后保持稳定，以真实负载调整。

统一内容能够同步，不等于复制账号、SSH 身份或虚拟机路径，也不等于其他三台已经运行成功。内容共享与运行可用性分别判断；本文件不增加部署任务。

## 二 四个首接队列

| 代号 | 首接队列 | 首接忙时的第一接替 | 对应关系的含义 |
|---|---|---|---|
| A | Web | G | A 承担一个普通接题席位和轻量协调，不再同时固定背 Misc/Forensics |
| B | Pwn | D | 保留此前七人框架中的初始 Pwn 方向，便于月底延续 |
| D | Reverse | B | 保留此前 Reverse 方向，Pwn 作为空闲时的接替 |
| G | Crypto | A | 保留此前 Crypto 方向，分配依据为覆盖而非 GPU 型号 |

这四个队列拥有同样的首接地位。不得把 A 先前的独有内容当作只能由 A 解某类题的理由。A 只协调冲突和阻塞，各人自行维护本人题目的验证、提交与 WP。

主队列没有题、题已完成或明确暂挂时，该成员立即可以接公共题或分担积压，不等待指定类型出现。官方未设置其中某类时，对应成员直接进入公共与积压队列。

## 三 Misc Forensics 和其他类别

Misc、Forensics 从开场就进入公共队列，四人均可接，不自动压给 A，也不要求等四个主要类型都做完。

公共队列的题由当前空闲且环境适合的人认领。多人同时空闲时，优先让已经掌握该题所需工具上下文的人接；仍无差别时按队内轮转决定，不依据 CPU/显卡名称虚构优势。一题只能确认一位负责人，其他人看到已认领就处理另一题。

流量取证按官方标签进入相应队列；标为 Misc/Forensics 的 PCAP 题仍是公共题。认领时看本机是否实际可调用 `forensics_pcap` 及底层依赖。新增能力包括概览、流定位、TCP 流读取、HTTP 对象导出、DNS 和 USB 原始字段提取。明确存在下一步处理机会的流量题，可以优先于已无新证据的主队列题；正在有效推进主线的人不因有新工具就被强制换题。USB 提取结果不是键盘明文还原，不能因此推定该题已接近完成。

Mobile、OSINT 或其他官方独立类别同样使用公共队列。若实际所需工具明显邻近某主线，可优先询问该主线的空闲成员；其正在有效推进主任务时不强制打断。

公共队列可以优先于首接队列。某个明确可验证的 Misc 机会很好时，空闲成员可以先接；官方类型决定队列归属，不决定题目难度、分值或优先级。

## 四 一人一题与积压分流

默认每人一个活跃主任务，因此四人最多四个主要任务。接替人只有当前空闲、原任务已完成或明确暂挂，并且相关工具可用时才接整题。两个人都在忙，题就排队，不隐含第五、第六个工作位。

典型分流：Pwn 积压而 D 无活跃 Reverse，D 可以接第二道 Pwn；Reverse 积压而 B 空闲，B 接第二道 Reverse；Crypto 积压而 A 空闲，A 接第二道 Crypto；Web 积压而 G 空闲，G 接第二道 Web。

第一接替人忙时，其他空闲且工具适合的成员也可以认领；都不合适则暂挂。首接不是某类题的独占权限，也不意味着所有主队列题必须等首接人做完。

A 的协调工作也算真实负载。如果 A 正在处理关键故障或调度冲突，就不能同时把他当作公共队列的空闲人。其他成员不把自己的验证、截图、WP 或正常提交交给 A 代办。

## 五 同一人面对多道题的选择

先完成已有候选且能立即真实验证的题，再比较有实证进展、下一步明确的题和全新题。对于新题，综合题值、预计投入、工具可用性和验证路径，优先选择当前最有希望取得可核对结果的机会。

不因首接类型固定而放弃其他类别的明确机会，不因另一人空闲而转走自己正在稳定推进的题。当前题只产生重复猜测、没有新证据时，可以保留进度后暂挂，接队列中条件更明确的一道。

`task_health` 的重复调用、连续失败，以及 80 次调用或累计工具耗时 30 分钟的提示，是复核信号，不是强制止损线。负责人先检查是否获得新证据、失败原因是否改变、下一步是否可验证，再决定继续、换方法、暂挂或交整题。不要为消除提示而重开任务；有明确进展时可继续并记录理由。这些统计不代表模型思考时长、Token 用量或已知费用，不能拿来比较成员模型成本。

NoobCTF 等新增经验检索对所有人开放，但按本题证据有选择地使用。参考答案默认与独立解题输入隔离；学习得到的方法仍须在当前题上验证，检索到旧题答案不能充当本题完成证据。

长计算等待期间，只有资源和监督条件允许时才做轻量读题；不默认再启动第二个重计算或动态调试。有人退出、账号不可用或机器失效时，同步减少活跃任务数，并优先移交接近验证的题。

## 六 官方标签与跨类方法

官方标签决定初始队列。题中出现另一类方法不要求重新分型，也不要求马上换人，因为四人拥有相同的共享方法资料。

例如图片里包含密码参数、Web 中包含 Wasm、APK 使用 AES，都由当前负责人先根据实际证据推进。需要换人时依据接替者的空闲程度、工具条件和具体新路线，而不只依据方法名字。

真正改变归属时转整题，连同原附件、已做步骤、脚本、证据和下一步一起交接。当前负责人变更后，旧负责人停止主动操作；不把流程拆成一人分析、一人长期代跑、一人补写 WP。

流量题的移交还应带上原始抓包、已用过滤条件、流编号、实际输出和导出对象；提供现有文件摘要与相对位置，保持与题目 WP 附件的对应关系。接收人优先复用已有证据，再核对关键结论，避免从概览开始重复跑完整流程。没有导出的文件或没有真实截图时如实记录，不补造。

## 七 硬件何时介入分题

| 条件 | 处理 |
|---|---|
| 普通 Web、脚本、静态分析、常规数学 | 按题型、空闲程度和实际进展分配，显卡不是分人依据 |
| CPU 密集 | 比较工具实际线程使用、VM 配额和剩余负载；A/D 可以作为候选，不保证总核数越多越快 |
| GPU 专用 | G 优先候选，前提是具体环境和工具实际支持并能调用 GPU；其他已具备能力的机器也可接 |
| 大镜像或内存密集 | 看当前宿主/客机内存余量；此次没有 E 的 32GB，不设置大内存专席 |
| Windows、特殊架构或专用调试环境 | 由当前有对应可用环境的人接，官方类型本身不保证每机环境可用 |

宿主 16GB 不代表 Kali 能使用全部 16GB；不能以文件大小直接推断固定峰值内存。当前 fpylll/angr 入口没有 GPU 调度，格约简或符号执行不因为 G 显卡型号就自动分给 G。

硬件真正影响题目时也采取整题转派。四机都不满足条件就如实暂挂，保留初筛结果。不给“同一份软件”附加“所有机器性能和可执行条件完全相同”的结论。

## 八 谁负责结果与 WP

当前负责人承担真实验证、按平台权限处理提交、保留该次回执和 WP。工具成功、格式正确、模型自信分别不能替代答案依据。平台接受与记录完整性分开报告，截图缺项也必须保留。

疑点可请空闲成员做限定范围的复核；不要求所有题都排队等 A 二次确认。若平台只允许统一操作入口，提交操作可以集中，但验证与 WP 责任仍归题目负责人。

跨机时保留来源。现有 ctf_progress 读取本机任务，不等于已经有跨机自动导入；接收人读移交包、关联团队题号、在本机接续，重要结论按实际条件复核。

## 九 调度示例

| 现场情况 | 处理 |
|---|---|
| Web/Pwn/Reverse/Crypto 都有合适题 | A/B/D/G 各接一题 |
| 一道清晰 Misc 比主队列里的探索题更有机会 | 空闲成员可以先认领 Misc，不强制先做主类 |
| 只有 Pwn 和 Reverse 较多 | B/D 各接一题，A/G 从同一题池选择工具可用的其他题；不会空等 Web/Crypto |
| 四人都在有效推进，又开放取证题 | 新题进入公共队列，先完成或明确暂挂旧任务的人接 |
| 公共流量题已能定位可读流或导出对象，某主线只有重复猜测 | 无进展主线先保存证据并明确暂挂；工具实际可用的空闲成员可优先接流量题 |
| 出现重复调用或连续失败提示 | 当前负责人检查新证据和可验证的下一步，再选择继续、换路或整题移交，不自动转给 A |
| USB 只导出原始数据 | 继续判断协议和还原条件，不把原始字段当作已恢复键盘输入 |
| 某题需实际已跑通的 GPU 环境 | 优先由空闲的 G 接整题；G 忙则在两题间比较机会，不能默认为第五个后台主任务 |
| 某机缺工具、账号失效 | 优先交空闲且条件适合的人；无可接人就暂挂，不把问题集中转给 A |

这些是规则的纸面推演，没有把它们当作四机实测或比赛结果。

## 十 已验证 未验证 未完成

### 已验证

四人名单、内容可以共享、赛方标明题型，均来自用户明确说明。本机新增流量六类动作、任务健康提示、NoobCTF 参考检索和 WP 数据附件已有部署验收记录；USB 当前边界是原始字段提取。当前四个主要队列分别有首接，公共题有明确认领规则，不依赖未参赛成员。部署验收不计作比赛解题率。

### 未验证

B/D/G 实际运行范围与账号可用性、任何个人专长排名、具体赛事题量和模型成功率。能够同步系统内容，不代表已经完成传输或部署，也不代表四机都已具备新增流量能力。未获得模型用量与单价时，不报告成本控制效果。

### 未完成

尚未提供具体赛题，没有实际认领或解题结果。本轮只更新分题方案，没有访问队友电脑、发送私有资料或修改运行系统。

## 十一 队内简版

A 首接 Web，B 首接 Pwn，D 首接 Reverse，G 首接 Crypto。Misc/Forensics 等公共题从开场就由空闲且工具适合的人认领。主队列积压可以整题分流；每人一次主攻一题，谁负责谁验证并保留 WP。A 只协调冲突，不是全队的默认代跑、复核和写作席位。
